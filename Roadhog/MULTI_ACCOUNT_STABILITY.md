# 多账号进程稳定性审查

审查日期：2026-09-22。本轮针对启动、停止、强杀、主界面异常退出和进程接管进行了独立源码复核及故障注入。使用真实测试进程、命名管道、文件和本机 UDP 模拟设备，没有操作桌面现用客户端或真实游戏设备。

## 修复的问题

1. **异常身份记录可能导致错误接管。** 原来仅凭文件中的账号、PID、启动时间和程序路径接管。现在先通过认证管道取得后台实际账号身份，再核对 PID、启动时间、程序路径，并保留操作系统进程句柄。无法验证的进程不接管、不强杀。结束前再次验证身份，仅结束该进程，不按进程名批量结束，也不结束整个进程树。
2. **启动窗口可能丢失后台。** 每次启动使用独立且不再修改的描述文件，另保留发现入口和待启动记录。主界面在后台发布身份前被杀，重开后会等待并接管原后台；身份文件丢失时可通过原管道再次发现，避免覆盖仍在启动的后台令牌。
3. **初始化卡住可能长期占用设备。** 后台先建立状态与控制通道，再构造硬件依赖。初始化有期限，超时回收进程；新的实例必须等旧实例结束后才能取得设备。授权未通过会显示错误并撤销自动启动意图，避免反复创建进程尝试授权。
4. **重复停止可能越过下一次启动。** 同一账号的并发停止共用一次操作；启动、停止和恢复通过该账号的独立执行门协调，旧停止请求不能再结束新一轮启动的进程。
5. **状态写盘失败可能拖住停止。** 停止进程和保存停止意图分别执行；写盘有三秒期限，失败会明确报告，不阻止释放输入或结束进程。
6. **关闭请求断连可能留下半关闭后台。** 后台接受关闭请求后自行完成关闭，不依赖主界面的管道继续在线。正常取消、释放输入及等待失败时，后台自己的关闭期限和主界面的强停作为兜底；硬件构造、原生读取或释放卡住也不会无限等待。
7. **主界面启动、配置编辑和退出之间存在竞态。** 初始化及界面异步操作统一跟踪和取消，退出前排空；已释放的管理器拒绝晚到的读取和启动。配置修改互斥，导入保存前重读账号列表。退出先关闭最深层授权窗口，再关闭硬件窗口；系统关机不被忙碌验证窗口否决，晚到回调不再访问已释放控件。
8. **强杀后可能遗留输入状态。** 新进程不能用本地“尚未连接”判断设备上没有按键按下。输入重置会先连接设备，再发送中性键盘和鼠标状态；业务启动沿用原有的输入重置入口。

## 故障行为

| 情况 | 处理 |
| --- | --- |
| 一个账号后台崩溃 | 主界面按退避间隔恢复该账号；其他账号保留原 PID |
| 一个后台卡住 | 该账号的操作有期限；状态管理和其他账号启停独立进行 |
| 主界面被强杀 | 已运行的后台继续运行；重新打开后验证身份并接管；主界面离线期间的进程重启管理暂停 |
| 启动中点击停止 | 取消启动、撤销恢复意图、回收后台，等待设备释放 |
| 连续点击停止再启动 | 停止完成前拒绝新启动；重复停止合并，完成后可以重新启动 |
| 身份记录错误或无法验证 | 报告原因，拒绝结束未知进程 |
| 正常退出或系统关机 | 先取消、释放输入和停止；超时只强停已确认归属的后台，界面等待有上限 |

进程隔离不能保证硬件、驱动、操作系统永远不出故障。瞬间强杀无法执行被杀进程的清理代码；软件在正常停止时先释放输入，并在重新连接时补做重置。设备断线或无法响应时，不能宣称物理按键已成功释放。

## 故障测试覆盖

- 同账号八轮并发启动、并发停止及快速重启，核对每个进程只启动一次业务。
- 三账号九次固定随机顺序强杀和恢复，核对其他账号 PID 与启动次数不变。
- 错账号、错误启动时间、错误令牌、损坏的身份文件，确认不会停止旁边账号。
- 状态管道正常但初始化永远不完成，确认超时回收和自动恢复开关生效。
- 身份文件丢失，以及真实管理器测试进程在后台首次发布身份前被杀，确认原 PID 与令牌被接管。
- 旧管理器释放后，旧设置窗口不能重新创建后台。
- 后台接受关闭后管道断开；依赖构造或原生操作不返回时，后台限时退出并可重新启动。
- 授权丢失时先释放输入，不被长操作持有的执行门挡住。
- 主界面初始化与退出、嵌套窗口关闭、系统关机、取消后的晚成功/晚失败回调。
- 本机 UDP 模拟 KMBox 的冷连接重置、握手失败、取消、释放失败后重连。

具体构建及回归结果见 [验证记录](MULTI_ACCOUNT_VALIDATION.md)。真实 DMA/KMBox 长时间运行、硬件断连重插及客户机原生驱动故障仍需实机验证；本轮测试不作为这些场景的性能或耐久实测结论。
