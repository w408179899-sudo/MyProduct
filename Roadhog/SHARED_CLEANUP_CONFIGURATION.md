# 清包与怪物过滤共享配置

总览页选择账号所属区服。首次迁移：脚本 1、2、3、4 属于一区，脚本 5、6 属于六区；未知账号标记为未分区。已有明确区服不覆盖。区服是账号属性，不随战斗方案切换；修改并保存后重启该账号生效。

`config/shared-cleanup.json` 是多账号客户端的共享配置来源：

- `common`：全账号共用白名单、黑名单、出售名单、摆摊名单与价格。
- `monsterFilters`：全账号共用怪物过滤；“刷新当前怪物”仍读取当前账号。
- `auctions`：以区服名称分组，分别保存物品、价格、查价方式。
- `migratedAccounts`：已迁移账号标识，防止重启后重新导入已删除的旧规则。

首次打开新版多账号客户端、或导入新账号时，自动备份并合并。备份在 `config/shared-cleanup-backups`，原有名单文件与引用保留。名单按完整关键字去重，不合并包含关系；摆摊取最高价；拍卖行只在同区合并，自动查价优先于手动，同为手动时取最高价。自动方式冲突时优先当前可用的“弹窗最低价”。仅有“搜索计算”的条目保留该方式，其算法仍是原有预留功能，不在本次实现范围内。

迁移优先采用原名单文件，文件不存在时采用有效账号方案，避免把账户内旧副本已经删除的词重新添加。不同名单间不互相删除条目。迁移失败不发布部分结果。已迁移账号不会再次导入旧文件；迁移标记 `shared-cleanup-migrated.json` 防止共享文件丢失后静默恢复过时名单。

运行处理顺序：**丢弃 → NPC 出售 → 拍卖行 → 摆摊**。名单不是互斥开关，各阶段仍受原流程开关控制。白名单仅阻止丢弃。分类规则与新增出售名单同时适用；丢弃胜过出售与后续交易名单。每个阶段重新检查剩余背包；前一阶段名单不阻止后续阶段处理剩余物品。

NPC 出售沿用已有未成交确认：出售篮清空、物品与金币均未变化时结束本轮，不反复提交；这不等于读取到游戏额度，也不新增每日停售状态。未成交物品可继续参与已启用的拍卖行、摆摊流程。各账号运行状态独立。

名单编辑自动保存，只合并本次条目变化；跨进程文件锁串行写入，原子替换让读取方始终看到完整文档。保存失败界面回滚。怪物过滤约 2 秒刷新；清包在每次新请求开始时读取并固定一份配置，中途及重试不会换规则。

验证入口：`Roadhog.Tests --test-filter="shared cleanup"`，以及 `--shared-cleanup-migration-audit <原config目录> <不存在的副本输出目录>`。审计仅在副本迁移，检查六账号分组、运行配置、重复迁移与原文件哈希，不启动游戏或硬件。
