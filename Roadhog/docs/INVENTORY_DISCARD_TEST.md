# 测试丢弃：实际 UI 定位与鼠标反馈

## 按钮行为

清包页“清理物品类型”右侧，在“测试摆摊”旁新增“测试丢弃”。按当前页面的规则、白名单和黑名单选取物品，无须先保存；每次最多处理 **3 项**，每项丢弃整叠。仍采用原有 `BagCleanupItemMatcher.SelectDiscardItems` 的优先级：白名单保护，黑名单强制丢弃，普通规则冲突出售优先，排除装备中的物品。

流程：打开背包 → 按实例 ID 找实际 UI 位置 → 核对悬停身份 → 按住左键分段移动到背包外 → 松开 → 核对确认框物品身份 → 动态定位主确认按钮 → 确认实例从背包消失。完成后保留背包窗口，便于核对结果。

本按钮与后台自动清包丢弃均不使用旧 `EstimateBagItemScreenPoint`、固定首格/格距/分页参数、鼠标推到左上角归零、复活点击位置或配置的丢弃确认坐标；也不把背包拖到左上角。旧坐标配置为兼容存档保留，不再参与丢弃动作。

测试执行时按钮禁用，摆摊与丢弃测试互斥，并复用 runtime 的手动输入与脚本互斥。关闭设置窗口会取消测试并释放输入。已在出售、摊位窗口打开、存在已有确认框、找不到目标或找不到释放位置时停止。等待动作确认超时不会盲目重复点击；失败时未处理的确认框可能保留，供人工检查。

## 共用实现与数据边界

- `InventoryInteractionDecoder.ReadBagItems`：复用已实测的摆摊定位方法，根据 UI 列表内容、实际行列数、格宽高、间距、父控件 bounds/client 原点定位，并核对实例 ID、模板与数量。
- `InventoryDiscardActions`：手动测试和后台 `BagCleanupDiscarder` 共用悬停核验、拖拽、动态确认按钮点击。点击后等待弹窗关闭或切换到另一层；未响应时停止，不重复点击同一弹窗。
- `FeedbackMouseMover`：通过官方 `ui_cursor` 快照读取鼠标实际位置，每步最大 70 像素、70ms 间隔，到目标 1 像素范围内才继续；同一实现供摆摊点击和丢弃拖拽使用。
- `InventoryInteractionDecoder.ReadInventory`：发布独立 `inventory_interaction` 官方快照。确认期间不把不可交互的背包格子暴露为操作目标。
- 新通道注册为 Stable；失败读取保留上次官方快照，冷启动等待首个有效发布，使用原有 provider 会话与失效机制。业务不接收底层读取错误或自行维护替代缓存。

## 2026-09-20：修复弹窗切换时提前退出

账号 2 的正式运行日志 `roadhog-20260920-083147-733.log` 记录：09:23:07 开始清理 20 项，成功校验删除 11 项。09:24:04 拖出第 12 项“匠人之高级武器提炼石”后，09:24:05 的 `inventory_interaction` 捕获遇到 UI 变化，provider 保留了上一份发布。旧控制器却通过独立的 `inventory_discard_confirm` 通道进入点击阶段，与动作使用的 UI 快照不同步，因“确认框对应的物品与本次目标不一致”退出。取消还遇到了输入键表不支持 `Escape` 的问题。

修复后的等待、确认、删除校验、受击/死亡交接和取消均使用 `inventory_interaction` 通道；`BagCleanupDiscarder.ReadConfirmationAsync` 只把同一官方 UI 快照投影为现有状态记录，不读取独立确认通道，也不建立第二份缓存。丢弃收包同样读取该 UI 通道。

关闭的确认框只有在库存已无目标时才直接进入删除校验，避免把“还没弹出”误当成“已经确认”。超时沿用取消和收包流程。`Escape` 已加入 `RoadhogInputKeyMap`，HID `0x29` 与现有 `Hardware.KmBox` 的 `KEY_ESCAPE`/`HidKeyboardMap` 一致。
