# 频道切换测试（2026-09-14）

总览保留固定频道下拉框，旁边为“切换测试”。选择本身只修改目标；点击按钮执行一次有界切换，使用当前选择，不要求先保存。选择“不固定”时按钮禁用。六组坐标编辑框移除，旧 JSON 坐标字段继续兼容保存，但生产切换流程不再使用它们。

手动测试要求本程序内账号脚本停止，期间禁止启动脚本。关闭配置窗口会取消测试；按下的左键在取消时释放。菜单、服务子菜单、频道窗口、下拉列表可以从已有打开状态继续。移动鼠标时使用游戏光标反馈，进入服务子菜单时先水平移动再向下移动，避免经过其他菜单项。

手动按钮和自动流程共用过图确认：点击“移动”之前验证选中频道和地图，提交后观察过图，待角色恢复再核对同一地图上的实际频道。菜单导航最多 45 秒，单个 UI 展开最多等待 5 秒；进入过图后持续等待或由用户取消，一次尝试最多提交一次“移动”。当前已经在目标频道时直接确认。

## 自动挂机调度

启动即检查实际频道；“不固定”关闭检查。频道不一致时连续脱战 15 秒才允许第一次尝试，以后从上一次尝试开始计时，至少间隔 60 秒，且每次都要满足脱战条件。不再因频道不一致回城、依赖复活路线或停住等待五分十秒。换图、切频道、回程、刚进入游戏所产生的五分钟冷却统一通过一分钟重试处理，不读取或推算准确冷却。

战斗计时使用已有正式数据：脚本战斗/目标状态、活的怪物锁定目标、指向角色或宠物的存活对象、角色掉血。死亡和场景/频道变化重置脱战观察。这里是现有战斗活动判断，没有新增服务器战斗计时字段。清包、采集、拾取、死亡恢复等独占流程中延后鼠标动作，仍继续原流程。

真正尝试前暂停移动、预瞄和跳跃，并释放 WASD 和右键，保留挂机路线与工作进度；导航时限为 45 秒，过程中反复检查战斗条件。最终点击开始前解除导航时限，之后每 200 毫秒观察过图；5 秒未过图则返回挂机，已过图则持续等待角色恢复并验证频道。超过 60 秒只告警，不提前恢复挂机，用户停止可以取消。失败保留窗口，下一次若窗口及目标选择仍在，只点“移动”；窗口被游戏关闭时重新打开。每次只提交一次移动。

启动时读取一次实际频道，已到目标或切换验证成功后记录本次运行完成，不再读取频道。修改目标或重启脚本后重新检查；不固定关闭检查。未完成时频道读取最多每分钟一次，脱战观察仍每秒执行，已有战斗状态在每次调度时打断脱战计时。切换细节见 `CHANNEL_TRANSITION_DATA.md`。

重试到期后进入 `fixed_channel.wait.begin`：先打完已在进行的战斗，停止下一只怪的预瞄和主动选怪；没有当前战斗时停下移动，保留路线进度，记录 `fixed_channel.wait.peace`。等待期间仍处理来袭怪物和死亡，战斗结束后重新等待完整 15 秒。已有拾取、清包、死亡恢复等独占任务继续原流程。尝试成功或失败后都解除等待限制；失败恢复正常挂机，从本次尝试开始至少一分钟后再次保留脱战窗口。这里的一分钟是最小重试间隔，不会为了准点切换而中断当前战斗。

## 数据边界

2026-09-14 18:58 账号 4 已提交移动并确认到频道 3，随后角色数据短暂不可读触发重连。Windows .NET Runtime 1026 确认闪退为 `Vmmsharp.Vmm.Dispose(Boolean)` / `Finalize()` 中的 `NullReferenceException`。本地 vmmsharp 5.16.12 的构造失败路径可能尚未赋值 LeechCore，而基类析构仍会直接调用其 Dispose。`SafeMemProcVmm` 覆盖这条清理路径：仅对已创建的 LeechCore 调用基类清理；未完成初始化时关闭可能已分配的原生句柄，不依赖派生类字段初始化。原厂 DLL 保持不变。

所有读取入口共享重连等待，连接移除后先等待正在进行的读取结束再释放，已经取到旧连接但尚未读取的调用会被拒绝；旧连接清理完成前不建立新连接。测试覆盖失败构造对象的显式清理、独立进程强制垃圾回收、读/释放并发和各读取入口的重连限制。原固定 10 秒等待已由过图和角色恢复确认替代。

2026-09-14 18:48 账号 4 启动后停住的日志显示：切换前读取 `world_objects` 时一直重试 `world_target_self_reference`，尚未进入鼠标步骤。只读实测捕获石背恐龟（对象 2235040718，血量 0/13315，目标为自身）。适配层现在仅在血量字段读取成功、当前血量为 0 且最大血量大于 0 时接受尸体的自指目标；活体或血量不明的自指仍按异常处理并保留上次正式目标。不会通过清空周围对象、跳过活怪检查或把读取失败当作脱战来恢复流程。

`ChannelSwitchUiDecoder` 属于 VMM 适配层，依据 2026-09-09 Game.dll 和账号 4 的实测字段解析。窗口表 Game.dll+0xD63990：17 为开始菜单，376/377 为菜单层，227 为频道移动；菜单所有者和开始按钮锚点用来排除其他弹出菜单。控件相对矩形加祖先客户区偏移得到屏幕位置。频道列表仅在完整显示、没有滚动时根据实际列表高度和条目数计算行位置，不猜测被裁剪的列表。

`channel_switch_ui` 注册在封闭的全 Stable 目录，通过现有 ReadStable/read-validate-publish 流程发布。指针、名字、条目范围、矩形、遍历边界及读取前后根/显隐/选择一致性由适配层校验；相关 UI 树整体提交，失败保留上次完整快照，冷启动在读取层重试，会话失效清除。业务只访问 `IRoadhogSnapshotReader` 的正式快照，不接触原始读结果、偏移或数据质量状态。
