# 卡刀

技能页在“条件抢连招”下一行提供“卡刀（每2技能）”和“等待ms”。技能列表及操作按钮整体下移，底部起手技能区域保持原位置。

- `SemiAuto.AttackWeaveEnabled`：默认 `false`，旧配置维持原来的技能执行流程。
- `SemiAuto.AttackWeaveDelayMs`：默认 `600`，范围 `0–10000`，随账号配置、方案和配置复制保存。
- 普通技能、条件技能、起手技能、触发前缀和连招的每一段共用成功计数。维护流程的补血、补蓝、召唤等按键不属于这个战斗技能序列。
- 只有已发送的技能对应的冷却结束值向前变化才确认一次释放。同一尝试的重按不重复计数，按键失败、缺少对应技能、冷却不变或回退均不计数。没有冷却变化证据的技能也不能直接用“按键成功”替代释放确认。
- 普通尝试沿用短确认超时；仍在连招确认流程中的起始段和当前段保留原始尝试，直到连招确认成功、结束或过期。即使冷却变化晚于 `ConfirmTimeoutMs`、期间多次重按或缺少技能快照，连招认可的成功也必须先计入卡刀，再决定是否释放下一段。连招离开这些节点后，不再延长其原有确认窗口。
- 距离上一次成功发送的技能按键**超过 1500ms**，主动清除本轮成功计数及待确认占位，从下一次技能重新计数；恰好 1500ms 不重置。每轮战斗循环及确认快照处理前检查，已卡住时也能释放名额，无需等待下一次按键。重按技能会刷新按键时间但不增加成功数；失败输入、补血等维护按键及 C 不刷新此时间。超时保留目标、连招位置与触发前缀进度，已丢弃尝试的迟到确认不加入新一轮。
- 已确认两个成功并进入等待 C 的阶段，不受上述 1500ms 重置影响，包括用户设置更长等待时间、C 输入失败后的重试。
- 第二个成功被确认时开始等待；等待结束点按一次 C，再继续后续技能。不会再额外等待一段 C 后延时。确认本身受现有快照轮询时机影响。
- 连招示例：第1段、第2段、等待、C、第3段、第4段、等待、C。连招位置保留，脚本内部连招截止时间补偿这段等待；游戏自身的连招有效时间不由脚本改变。
- “开怪按C”与卡刀独立。卡刀的 C 不计为技能；C 输入失败会保留当前等待状态并限速重试，成功后才继续技能。
- 计数按账号隔离；失去或更换战斗目标、死亡、停止、关闭卡刀时清除未完成的计数与待按 C。

`AttackWeaveState` 负责尝试去重、确认计数和等待时刻；`SemiAutoCombatController.AttackWeave.cs` 使用现有快照和键盘接口编排，不启动后台按键循环。等待期间由账号 worker 继续运行生命检查。

诊断事件：`semi_auto.attack_weave.skill_confirmed`、`semi_auto.attack_weave.wait_started`、`semi_auto.attack_weave.pressed`；超时重置记录 `semi_auto.attack_weave.idle_reset`，包含空闲时间、原成功数及是否有待确认占位；C 发送失败沿用 `semi_auto.attack_key.failed`。

测试入口：`Roadhog.Tests.exe --test-filter="attack weave"`。测试覆盖成功确认、重试去重、完整六段连招、普通技能与连招混合、触发前缀与起手技能、失败输入、C 重试、目标切换、死亡与停止、关闭兼容、账号隔离、配置持久化及 UI 布局。延迟确认回归覆盖按键间隔 1500ms 内普通和精灵连招的每一组两段、起始段与第二段一起晚到、中间缺少快照，以及连招过期或取消后的清理。空闲超时回归覆盖已成功一次后连招首段未确认的实际卡住场景、双占位、仅剩一个成功计数、1500/1501ms 边界、精灵重试刷新时间及超时后的重新计数、长时间等待 C 和 C 失败重试。
