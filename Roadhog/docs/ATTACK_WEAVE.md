# 卡刀

技能页提供“卡刀（每2技能）”和“等待ms”，与共用起手技能一起使用当前技能栏释放引擎。

- `SemiAuto.AttackWeaveEnabled`：默认 `false`，没有此字段的旧配置不启用卡刀。
- `SemiAuto.AttackWeaveDelayMs`：默认 `600`，范围 `0–10000`，随账号配置、方案和配置复制保存。
- 维护流程的补血、补蓝、召唤等按键不属于战斗技能计数。

`QuickbarAttackWeaveState` 负责尝试去重、冷却确认计数和等待时刻；`QuickbarSkillCombatController.AttackWeave.cs` 及共用起手编排 `SemiAutoCombatController.QuickbarAttackWeave.cs` 使用现有快照和键盘接口，不启动后台按键循环。等待期间由账号 worker 继续运行生命检查。旧主攻击调度已退役，参见[统一技能栏释放](skill-release-migration.md)。

## 技能栏可用

技能栏释放使用账号卡刀开关和等待配置；默认关闭。未勾选时沿用原来的选技能、确认、读取次数与 80ms 轮询节拍，不增加快照读取或卡刀等待。

- 执行树的普通技能、条件与触发技能、每个连招段及共用起手技能共用计数。脚本成功按下本次可用的对应技能后，检测到该技能 CD 结束值向前推进就计一次；每两个计数后等待设置时长，点按一次 C。开怪 C 不参与计数，也不清除已计一次的计数。
- 卡刀计数与执行器的释放确认分离，不再等待最后释放技能 ID 或时间更新。释放记录单独变化而 CD 未变、仅变暗或出现下一段图标、未发送对应技能的 CD、失败输入、CD 不变或回退、没有 CD 的技能均不计数。按键前缺少对应技能快照不能构造 CD 基线；重按保留首次成功按键的基线，同一次 CD 推进只计一次。技能执行器原有释放确认、重按和连招交接保持原逻辑。
- `QuickbarAttackWeaveState` 保存每账号的确认计数、成功发送尝试身份和单调等待时间。超过 1500ms 的技能按键空闲清除未完成的计数，已安排的 C 等待及失败重试不受该阈值影响。C 失败至少间隔 100ms 重试；C 按键成功完成后固定等待 30ms，才允许后续技能（包括起手与连招）。例如配置 800ms：两次确认 → 等待 800ms → C → 等待 30ms → 后续技能。后置等待仍保留生命、目标及维护检查。
- 等待期间每轮保留原有生命、目标与维护检查，发送 C 前再核对官方状态。维护接管、死亡、停止、目标切换、技能页或绑定改变、关闭开关会清除待卡刀；补血、补蓝及清包等维护流程优先。
- 卡刀保留当前连招位置，但不延长连招窗口，不使暗掉或过期的技能可用。等待结束仍按官方 `CanUse` 和原有冷却规则继续。
- 后段接管按键后仍保留前段未计数的 CD 尝试，在其确认期限及 1500ms 空闲规则内接受迟到的 CD 推进。启用卡刀时，只把尚待计数的准确技能 ID 并入原有技能读取；等待 C 时仍观察这些技能的 CD。批量 CD 证据每轮最多计两个，其余已观察到的证据与尚未消费的尝试跨 C 保留，后置 30ms 结束后继续下一轮；取消或停止时一并清除。
- 共用起手技能独立确认并加入计数；起手列表与开怪等待流程均可继续执行。

诊断事件使用 `quickbar_skill.attack_weave.skill_confirmed`（`evidence=cooldown_started`）、`wait_started`、`pressed`、`press_failed`、`idle_reset` 后缀。专项测试使用 `--test-filter="quickbar attack weave"`，覆盖 CD 与释放记录独立、普通/条件/触发/连招/起手、迟到前段、重按与失败去重、CD 回退与时钟回绕、跨 C 证据及后置延迟、生命周期清理和关闭兼容，同时回归 `--test-filter="skill tree release"`、`--test-filter="attack weave"` 与共用起手流程。
