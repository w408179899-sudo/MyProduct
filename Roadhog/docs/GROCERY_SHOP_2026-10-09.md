# 杂货摆摊与每日定时出发

## 配置和手动实机测试

1. 在“路径 → 杂货摆摊路径”中，从所选卷轴的回程落点录制到摆摊终点，保存并选择这条路径。路径必须带地图编号和至少一个点；回程后核对地图及首点附近位置，确认前不会走路。
2. 同页选择“回程卷轴”。“刷新背包卷轴”读取所选账号背包，只列出卷轴大类18中静态使用组36的返程物品，例如“伏魔殿返程咒语书”“贝达扎尔村返程珠”。疾走、狂风等增益卷轴虽然也属于大类18，但使用组为31，不进入列表；筛选不依赖名称关键词。列表按名称去重，只包含有数量的未装备背包物品；刷新保留原选择，缺失物品不会作为背包候选项。也可以填写物品完整名称。实际执行按完整名称匹配，不使用关键词替代另一种卷轴。
3. 在清包页配置摆摊物品名单和原来的4～9折折扣。打开摊位前读取角色姿态；处于战斗姿态时按一次X，等待确认普通姿态再继续。摊位文字沿用现有行为：36个对应折扣数字；输入后点击摊位第一格失去焦点，再打开背包登记。
4. 清包页顶部使用“正常清包 / 杂货摆摊”单选按钮切换方式。杂货模式在上方集中显示定时、每日时间列表、临时手动按钮及“回程 / 路线设置”快捷入口；正常模式显示出售、拍卖行、转移金币、摆摊及仓库配置。切换模式保留已有定时、交易、仓库和物品规则配置。勾选“自动清包”后按“剩余格低于”阈值先触发原地丢弃检查，仍不足且无物可丢时出发；定时可单独勾选，按北京时间每日重复，支持添加、修改、删除多个HH:mm时间，跳过出发前丢弃检查。保存后，下一次普通启动使用新配置。
5. 本次临时保留“手动杂货摆摊”按钮。按钮先保存当前设置，再向对应账号提交同一条杂货流程，忽略背包空位阈值；停止中的账号会启动，运行中的账号接收任务。手动提交不会把保存的“正常清包”选项强制改成杂货模式。

## 流程和中断

- 所选卷轴缺失：记录跳过原因，不执行丢弃、回程、走路或摆摊，不写成功时间。
- 背包触发先按当前规则原地丢弃，确认待丢物品耗尽后重新读取空位。空位恢复到“剩余格低于”阈值即结束本次任务并继续挂机；只有空位仍低于阈值且已无可丢弃物品时才出发摆摊。关闭背包后新增的待丢物品也会重新检查。操作失败、受攻击、死亡或停止不能当作“无物可丢”；输入失败保留本次原地丢弃任务等待重试，战斗/死亡中断交回原有战斗/复活处理。选中的卷轴在出发前丢弃阶段也受到保护。
- 定时和手动触发跳过上述出发前丢弃及空位检查，不要求背包满，也不要求丢弃规则已耗尽。
- 通过对应入口检查并确认有所选卷轴及可摆摊物品后，打开背包使用卷轴，等待确认回程落点，再沿杂货路径到终点摆摊。全部售罄后仍按当前丢弃规则清理剩余背包物品，完成后重启脚本；选中的卷轴在本次任务内受到保护，不丢弃，也不登记到摊位。出发后不因回程途中空位变化而取消摆摊。
- 没有符合摆摊名单且具有有效系统价格的物品时，不出发，不当作售罄。
- 打开背包，定位卷轴，核对物品身份与悬停，再右键一次。读条约10秒，必须等场景确认传送及正确落点；随后关闭背包，按路径顺序走到终点，执行已有折扣摆摊和全部批次售罄确认。定时和手动入口中，重叠的摆摊/丢弃规则仍先摆摊；背包入口先按丢弃规则处理，出发时重新生成剩余物品的摆摊计划。
- 加载前发现怪物正在攻击或角色掉血：Escape取消读条，关闭可安全关闭的背包并释放输入，清除本次任务，交还正常战斗；不执行售后丢弃。打完怪并完成原有拾取后，重新判断背包或尚未完成的定时条件；没有新增完整清包冷却。
- 使用后20秒仍未确认出发：取消读条，并再次读取场景。只有确认还在原地才结束本次；若传送恰好开始，则继续等待落点。同一次尝试不会再次右键卷轴。
- 一旦已经加载地图，不根据旧地图攻击者取消，不根据固定10秒直接认定成功。加载较慢或落点错误时等待正确官方场景，可通过停止账号取消。
- 售罄前停止、死亡和操作失败均不会写成功时间。全部售罄后立即保存实际售罄时间，再执行丢弃；售后丢弃失败保留已经保存的售罄时间，不发布重启信号。交易、成功记录保存或售后丢弃操作失败沿用摆摊暂停机制，避免自动重复不确定的交易。

## 定时完成记录

每个账号只持久保存最后一次全部售罄的实际时间，含日期，存放在账号配置目录下的`grocery-shop-success`，按账号实例标识隔离。保存采用临时文件原子替换，不随停止或重新启动丢失；不保存“某个定时点已经按过卷轴”的记录。

当前最近一个已经到点的每日时间晚于最后售罄时间，就仍需执行。中断、缺卷轴、没有可卖物品不会消耗这个时间点。正在执行时不排第二条任务，多次错过的时间点合并为一次；首次无成功记录也按最近已到点时间判断，支持补做跨日未完成的出发。

例如计划12:00与19:00，12:00出发后持续卖到20:00：售罄保存20:00，19:00自动被覆盖，不再补做。背包触发完成的杂货摆摊也更新这一个售罄时间。

成功时间保存且售后丢弃完成后，才发布现有的完成信号，交由账号管理器执行真正的Stop/Start。旧worker不直接回到战斗；正常启动重新读取账号配置，不重放手动任务。
