# 复活、打怪路径绑定原地打半径

## 操作与生效时机

在「路径 → 复活路径」和「路径 → 打怪路径」的「打开路径文件夹」右侧提供：

`☑ 绑定原地打半径  [30.0] 米`

- 勾选后可填写 1–500 米，点击「保存到列表」把绑定保存到共享路径文件。
- 不勾选时输入框禁用，该路径不覆盖半径。运行时依次使用：复活路径有效绑定 → 打怪路径有效绑定 → 方案原值。
- 切换路径时加载该路径自己的绑定；旧路径默认未绑定。
- 两边都绑定时优先使用复活路径：原地打驻点本身取自复活路径终点；未配置复活绑定时保留之前打怪路径绑定的效果。
- 账号选择的复活、打怪路径名称仍通过右上角「保存配置」保存。
- 每次启动账号，在方案加载完成之后、工作循环开始之前应用绑定；运行中修改路径文件不热更新半径，停止并重新启动后生效。

## 影响范围

- 只应用于「自定义打怪 → 原地打」使用的 `StationaryCombatRadius`，包括现有使用该值的选怪、回位和组队目标范围判断。
- 不修改路径打怪的 `PathCombatRadius`、复活路径的 `RevivePathAggressiveClearRadius`、采集和半自动模式。
- 绑定保存在共享路径中，引用同一路径的原地打账号共用该绑定值；每个账号启动时持有独立副本。
- 不把绑定值写回账号或方案。两条路径均取消绑定并保存后，下次启动恢复方案原值。
- 复活、打怪子页都能编辑绑定。两页打开同一文件时，未修改绑定的保存会保留文件中的最新值，明确修改绑定时以本次保存为准。
- 清包、采集子页保存时保留绑定；复活、打怪子页保存时保留已有清包 NPC 和点击坐标。

## 数据与兼容

路径 JSON 增加可选字段 `BoundStationaryCombatRadius`。字段缺失或为 `null` 表示未绑定；保存未绑定路径时省略该字段，路径版本仍为 1，不批量迁移旧文件。

启动时某条路径缺失、未绑定或绑定无效时，继续检查下一来源；两条路径均没有有效绑定时保留方案原半径。同名路径只读取一次。加载失败和无效数值有对应日志；不会把 0 或默认 30 写回旧设置。没有 `ScriptSettings` 的旧账号保持原有处理流程。

新程序可读取旧路径。旧程序不识别新增绑定，重新保存路径时可能丢弃该字段，因此应使用新程序编辑已绑定路径。

运行日志：

- `stationary_combat.path_radius.applied`：账号、路径名、来源 `pathKind`（`revive` / `combat`）、方案原值、实际绑定值。
- `stationary_combat.path_radius.load_failed`：当前来源读取失败，继续检查下一来源。
- `stationary_combat.path_radius.invalid`：当前来源数值无效，继续检查下一来源。

## 回归验证

`Roadhog.Tests/CombatPathRadiusBindingTests.cs` 覆盖旧 JSON、绑定和取消绑定的保存加载、非法数值、模式边界、启动应用、方案及运行副本隔离、重启刷新，以及真实 WinForms 控件的勾选、切换、保存和跨路径子页元数据保留。

定向测试参数：`--test-filter=path radius binding`。测试使用模拟接口和临时文件，不依赖游戏客户端。
