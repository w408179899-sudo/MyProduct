# 每日定时挂机与重新登录

在账号设置的 **总览 → 定时计划（当前账号）** 中配置，点击“保存配置”立即更新主界面的调度计划。默认两项均关闭，重登时间预填 `22:00`（晚上十点），旧账号配置维持原有行为。

## 配置示例

- 每天 08:00–22:00 挂机：勾选“定时挂机”，上线填 `08:00`、下线填 `22:00`。到点上线使用现有登录与挂机流程；到点下线提交正常退出游戏请求，确认 Aion 进程消失后保持下线。
- 每天 10:00 重新登录：勾选“定时重登”，填写 `10:00`。也可填写 `10:00,18:00`，一天最多 24 个时刻，保存时去重排序。
- 两项可以同时开启。固定重登仅在挂机时间区间内执行；若下线与重登同一时刻，下线优先。
- 一个账号每天配置一个挂机区间，支持 `22:00`–`08:00` 这样的跨午夜区间。上线包含起点，下线不包含终点；起止不能相同。

时间使用北京时间（UTC+8），格式为 24 小时制 `HH:mm`。计划跟随当前账号，切换战斗方案不会切换计划。启用前需在“设备/角色”中保存游戏登录账号与密码，并完成现有硬件验证。主界面需要保持运行；本功能不是 Windows 系统定时任务。

## 手动操作与恢复

手动点击“停止”后，本次保持停止，到下一次计划上线时间才自动启动。例如 08:00–22:00 的计划中，09:00 点击停止，会等到次日 08:00，期间 10:00 的重登也不会启动账号。只启用固定重登时，下一次固定重登时刻就是恢复时间。该暂停记录在重开主界面后仍然有效；用户主动启动成功会解除暂停。

计划下线区间内，普通启动、重新登录和自动恢复均不能重新启动挂机；需要先在总览中调整或关闭计划。关闭已停止账号的设置窗口只释放闲置后台，不视为用户点击“停止”。

在挂机时段打开主界面，可以按计划启动；固定重登不会补执行打开前错过的时刻。已提交的固定重登记录按账号保存，重开主界面不重复提交。设备忙等启动准入失败时，同一主界面会保留待执行任务，30 秒后重试，不抢占其他账号设备；到下线时刻则丢弃待执行重登，优先退出。

到下线时刻若仍在登录或重登，调度器取消当前启动并转入退出流程。真正退出游戏仍复用现有战斗准备、取消倒计时和进程消失确认，遇到战斗会等待处理，不能保证在时刻到达的同一秒完成退出。手动“停止”沿用原有停止脚本行为，不等同于退出游戏。

## 模块边界

- `DailyGameScheduleSettings`：账号配置、格式校验、深拷贝；不属于共享战斗方案。
- `DailyGameSchedule`：纯时间决策，处理北京时间、跨午夜、下线优先和手动暂停。
- `WorkerProcessManager.Schedule`：管理器调度、取消、重试和持久化，调用已有启动/退出/重登链路，不读取游戏内存或发送游戏输入。
- `AccountSettingsForm.Schedule`：总览控件与保存校验，保存后通知主界面更新计划。

执行记录保存在账号配置目录的 `workers/daily-schedules.json`，通过临时文件替换写入。状态文件损坏时不猜测是否已执行，自动调度暂停并记录 `schedule.state.invalid`；手动操作仍可使用。调度完成与重试分别记录 `schedule.completed`、`schedule.retry`。
