# 杂货售空后可选 NPC 出售

## 配置与流程

- `Maintenance.CleanupWorkflow.GroceryPostSaleAction`：默认 `Discard = 0`，保留原售空丢弃；`NpcSell = 1` 选择 NPC 出售。
- `Paths.BagCleanupReturnItemName`：清包路径页刷新并选择背包返程物品。未选择时，普通清包保留原 `BagCleanupTownReturnKey` / `TownReturnKey` 兼容行为；NPC 杂货分支要求明确选择物品。
- NPC 分支复用清包路径与该路径的 `CleanupNpcName`，要求路径地图和入口有效。摆摊回程与清包回程使用同一种消耗品时，出发前检查至少两份，并保护两段回程物品。
- 有摆摊候选：回程 → 杂货路线 → 全部售罄并保存真实时间 → 清包回程 → 清包路径 → NPC 出售 → 请求重启。
- 无摆摊候选：直接清包回程和 NPC 出售；不伪造摆摊售罄时间。
- 背包满触发前，仍先按原规则原地丢弃、重新检查空位。这个步骤不使用 NPC 可售筛选。
- 已处于相同地图的路线入口 5 米内且高度差不超过 2 米时，无需再使用卷轴。避免同城落点附近传送位移过小、没有加载帧时重复消耗卷轴。

进入 NPC 出售页后，先点击一次“杂货全部登录”，再点击一次“出售”，确认这批成交后才开始手动登录。首批采用游戏按钮实际登录的杂货，不要求属于原丢弃名单，也不拆成三条；如果按钮登录了白名单或回程物品，则停止提交。没有杂货时仍点击一次空列表的出售按钮，再继续后续流程。

NPC 手动登录候选是**原丢弃候选且当前可出售的物品**，不按物品类型排除。白名单与回程物品保护仍生效。不可售物品留在背包；其他物品按系统单价、背包格排序，每三条背包记录提交一次，不足三条也提交。每条记录保留整叠数量。NPC 登记直接移到目标物品，不经过固定点，继续核对悬停实例、模板和数量。自动杂货首批完成后重新读取背包，避免重复登录已经卖出的物品。

每批核对 NPC 身份、待售实例和数量、按钮及窗口状态。提交后同时确认待售列表清空、物品移除、金币增加。未成交或结果不明确时保留剩余物品并暂停，不重复提交、不自动转为丢弃。普通 NPC 清包默认单条批次不变。
