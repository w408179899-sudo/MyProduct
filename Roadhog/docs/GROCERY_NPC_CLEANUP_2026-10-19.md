# 杂货售空后可选 NPC 出售

## 配置与流程

- `Maintenance.CleanupWorkflow.GroceryPostSaleAction`：默认 `Discard = 0`，保留原售空丢弃；`NpcSell = 1` 选择 NPC 出售。
- `Paths.BagCleanupReturnItemName`：清包路径页刷新并选择背包返程物品。未选择时，普通清包保留原 `BagCleanupTownReturnKey` / `TownReturnKey` 兼容行为；NPC 杂货分支要求明确选择物品。
- NPC 分支复用清包路径与该路径的 `CleanupNpcName`，要求路径地图和入口有效。摆摊回程与清包回程使用同一种消耗品时，出发前检查至少两份，并保护两段回程物品。
- 有摆摊候选：回程 → 杂货路线 → 全部售罄并保存真实时间 → 清包回程 → 清包路径 → NPC 出售 → 请求重启。
- 无摆摊候选：直接清包回程和 NPC 出售；不伪造摆摊售罄时间。
- 背包满触发前，仍先按原规则原地丢弃、重新检查空位。这个步骤不使用 NPC 可售筛选。
- 当前与路径的地图编号相同，任一路径点水平距离严格小于 100 米且高度差不超过 2 米时，跳过回程，从最近合格点沿原顺序走到终点。普通清包、拍卖行、仓库、杂货摆摊与售后 NPC 共用此规则。

进入 NPC 出售页后，先点击一次“杂货全部登录”，再点击一次“出售”，确认这批成交后才开始手动登录。首批采用游戏按钮实际登录的杂货，不要求属于原丢弃名单，也不拆成三条；如果按钮登录了白名单或回程物品，则停止提交。没有杂货时仍点击一次空列表的出售按钮，再继续后续流程。

NPC 手动登录候选是**原丢弃候选且当前可出售的物品**，不按物品类型排除。白名单与回程物品保护仍生效。不可售物品留在背包；其他物品按系统单价、背包格排序，每三条背包记录提交一次，不足三条也提交。每条记录保留整叠数量。NPC 登记直接移到目标物品，不经过固定点，继续核对悬停实例、模板和数量。自动杂货首批完成后重新读取背包，避免重复登录已经卖出的物品。

每批核对 NPC 身份、待售实例和数量、按钮及窗口状态。提交后同时确认待售列表清空、物品移除、金币增加。按 2026-10-19 后续要求，杂货 NPC 分支在未成交、限卖或结果不明确时保留剩余物品，结束当前出售步骤；尽力按空格关窗，继续可执行的补箭步骤，最后重启脚本。不重复提交该批次，不自动转为丢弃。普通 NPC 清包默认单条批次不变。

## 追加：售空后失败继续后续步骤

用户明确要求限卖、无法出售和任一步骤异常都不能阻塞后续流程。本节替代前面历史记录中的“NPC 出售失败后暂停，不重启”行为。

- 杂货 NPC 链路独立处理前往商人、出售、空格关窗和补箭。限卖、明确未成交或出售异常结束本次出售，保留剩余物品，不重复提交、不改为丢弃。
- 尽力按空格关窗；若窗口未关闭，短暂等待后按 Escape 取消弹窗，再按空格。输入失败、关窗失败和背包关闭失败分别记录，不阻塞后续步骤。
- 已抵达商人时仍尝试弓星补箭。购买前仍验证当前窗口、NPC、商品和金币；购买异常只提交本次一次，尽力关窗后结束，不在该次流程重试付款。
- 回程或路径失败时，跳过依赖抵达商人的出售和购买，执行收尾并交给原有脚本重启流程。无可摆摊物品直接走 NPC 时也使用同一规则。
- NPC 模式确认摊位售空后，成功时间写入失败只记录警告，后面的 NPC 流程仍执行。worker 对该阶段意外抛出的异常还有最终收尾入口，避免重新落入永久暂停分支。
- 所有异常记录 `grocery_shop.stage_skipped` 的 `stage` 与 `error`；NPC 完成日志携带 `saleCompleted` 和 `skippedStages`，失败不会被记录成已成功卖完。
- 用户手动停止继续传播取消，立即结束，不按后续空格、不发出重启请求。原地丢弃、独立补箭请求以及普通清包仍保留各自规则。
