# 清包与交易流程

## 使用与兼容

- 主界面原“登录”按钮改为“清包”，手动点击先确认，按清包页所选项目执行。运行中的账号通过同一 worker 插入流程，先停止选新怪并处理当前战斗，再使用清包回城按键，确认位置迁移后才打开背包丢弃。空闲账号同样先回城清包，再按原模式启动挂机。
- 四个项目顺序固定：出售 / 丢弃 → 拍卖行 → 转移金币 → 摆摊。可分别勾选。旧配置默认只启用普通清包。
- 自动触发遵守自动开关、背包阈值和 25 分钟完整清包冷却。先在原地清完可丢弃物品，再读背包空位；空位恢复就继续挂机，即使仍有可出售物品或勾选了拍卖行，也不因此回城。只有空位仍低于阈值、没有可丢弃物品且完整清包冷却允许时，才按清包回城键安全回城，确认位置变化后执行出售等所选流程，再返回挂机点。原地丢弃不启动完整清包冷却，冷却期间仍可丢弃。自动永不执行转移金币或摆摊，也不显示确认弹窗。
- 每个 worker 会话仅允许一个请求；停止取消整个流程，未完成请求不继承到下一次启动。回城未确认或丢弃未完成时保留请求，每隔 2 秒重新尝试，不进入出售、拍卖行或普通挂机。已确认回城后的丢弃重试不会再次回城。后续出售或交易失败仍结束本次请求并记录告警，不能假定交易已成交，也不立即重复提交；自动清包至少等待 30 秒，完整出售 / 拍卖流程进入原有冷却。丢弃被攻击打断或清包期间死亡时，先处理战斗 / 复活，再重新检查背包；死亡会重置手动回城确认。
- 状态列显示“清包中 / 等仓库 / 摆摊中”，悬停显示当前步骤、等待秒数或剩余项数；正常进度不占用原告警通道。

## 路径和物品

新增拍卖行路径、摆摊路径编辑页，复用现有录制、保存、选择、删除、复制、单次执行功能。清包、拍卖行、摆摊路径相互独立，共用录制起点；手动清包先回城，因此该起点需能从回城落点衔接。流程从第一个点执行，不能使用“最近点”跳过路径前段。

普通出售完成后逆走清包路径；拍卖行完成后逆走拍卖行路径。转移金币和摆摊共用一次摆摊路径，先购买再出售。结束时按回城键，确认坐标迁移，再走复活路径，绝不逆走摆摊路径。所有已选阶段的路径、仓库名和按键先预检，避免执行一半才发现后续路径未配置。

白名单仅阻止丢弃（包括黑名单指定的丢弃），不阻止 NPC 出售、拍卖行或摆摊。拍卖行名单优先保留，不进入普通出售 / 丢弃；未开启拍卖行、满额或查价不可用时也不降级出售。其余物品先应用显式丢弃黑名单，再按 NPC 出售规则处理；同时在摆摊名单中的物品也优先卖给 NPC，之后只对实际剩余背包物品生成摆摊计划。摆摊名单仍阻止普通类别规则丢弃，避免未命中出售规则的物品被提前清掉，但不阻止显式黑名单丢弃。两份交易名单重叠时拍卖行优先。NPC 正常拒绝整批交易时结束该阶段并继续后续流程；模糊结果或操作异常仍停止，具体证据见下文。摆摊计划在购买仓库物品之前冻结实例和数量；买入物品即使合并进同一叠，也不会增加本轮出售数量。

装备分类排除魔石，避免“魔石:盾牌防御”因名称含“盾”命中装备出售；类型 3 的武器（包括宝玉、枪）同样按装备规则处理，不依赖名称关键词。

手动清包先回城再丢弃，自动触发仍在当前地点先丢弃。丢弃没有整段时长限制或项目数上限，也不会因空位超过阈值而提前结束；逐项验证物品已离开背包，关包后再次读取候选。自动请求清完后复查空位，决定结束原地清包还是安全回城，不能只凭存在出售候选直接加载清包路径。手动请求按完整所选流程执行，不受背包阈值限制。单件悬停、弹窗、确认次数及超时保护继续保留，校验失败先取消当前操作、收包，再从剩余实际物品重试。已进入完整流程后，没有可出售物品就跳过商人阶段，继续后续已选流程。完整清包冷却期间保留全部规则判断物品归属，只禁止 NPC 出售和拍卖行；不会删除出售规则后将本应出售的物品重新归入丢弃。

挂机期间两个正式入口均保留未完成的丢弃：统一 worker 保存自动清包请求；打怪后的维护入口保持 `WaitDiscardRetry` 活动状态，按 tick 等待重试，不放行普通战斗 / 维护。悬停不匹配、单件超时、输入异常或关闭背包失败不再结束整批任务。关包后即使空位已足够，也要清完新读取到的候选；只有候选为零且确认窗口清空才记录完成。怪物攻击可以立即中断丢弃并交接战斗，死亡保护与手动停止仍有优先权。

手动请求预检清包回城按键（留空时兼容使用普通回城按键）和复活路径。即使只勾选普通清包或拍卖行，完成后也沿复活路径返回挂机点。清包 / 拍卖行路径必须能从实际回城落点衔接；转移 / 摆摊结束后的回城与复活返回保持原行为。

统一清包流程中的 NPC 出售使用 `npc_trade` 正式快照：确认配置的商人及对话，按“出售道具 / 出售物品”控件定位开窗。每次只登记并提交一个背包条目，叠放物品保持整叠数量；按正式背包快照中的系统出售单价 `VendorSellUnitPrice` 从低到高出售，同价按背包格子排序，不再将武器单独排到最后。进入出售阶段时只将背包置顶一次，后续保持背包打开，每次读取当前物品坐标和悬停身份，核实出售列表实例、模板及完整数量。出售按钮未被背包矩形覆盖时才发布可点击坐标，实际遮挡或外来弹窗仍阻止点击。提交一次后同时等待列表清空、对应背包实例移除、金币增加；只有金币增加不能算本次成功。阶段结束后再关闭背包。旧独立清包入口保持原兼容行为。

达到 NPC 售卖限额时，游戏可能清空出售列表，但物品和金币都不变。提交后仍完整等待最多 8 秒核对正常成交；确认等待到期后，只有正式快照证明同一 NPC 出售窗仍有效、背包仍打开、出售列表为空、本次实例 / 模板 / 数量均未变化且金币相同，才记录 `bag_cleanup.sell.no_sale` 并正常结束 NPC 阶段，沿路径返回后继续拍卖行和后续摆摊，不重复提交这笔交易。未读到直接的限额字段，因此日志描述可验证的“未成交”，不宣称识别了限额数值。部分物品减少、只有金币变化、列表未清空、目标 / 弹窗改变、读取异常和取消均不能进入这个分支。

## 拍卖行

通过 F8 选择交易中介：名字“摩比隆”或正式快照确认标题为“交易中介”。按 C 后等待真实对话和“委托交易”控件，开窗验证。进入后固定按“全部撤单 → 按配置登录物品 → 计算领取金币”的顺序执行。上架阶段结束后再到计算页领取已售金币，确认背包金币增加且结算金额清零。

拍卖行路径增加与清包路径一致的“刷新附近 NPC”及下拉选择。选择后点击“保存到列表”，NPC 名称保存在该路径的 `AuctionNpcName`，独立于清包商人名称。正式流程及“测试拍卖行”都使用保存的名称，同时验证交易中介身份；未配置名称的旧路径继续按原来的名字 / 标题规则选择。F8 未选中时会重试，期间轮询目标数据，停止可取消。

支持手动单价、弹窗最低参考价。自动方式不使用保留的手动价格；最低参考价与最低允许售价是两个字段。没有有效报价、价格不合法、手动价格留空时保留物品。搜索计算算法尚未定义，因此正式流程保留该模式的物品并记录原因；现有“测试拍卖行”仍可搜索报价，且不提交交易或领取金币。

“弹窗最低价”可按物品设置 8.01～9.99 折，最多输入两位小数，显示补足两位。折扣单价为 `floor(市场最低单价 × 折扣 ÷ 10)`，保底单价为 `ceil(背包系统单价 VendorSellUnitPrice ÷ 20)`；最终取折扣价、保底价、游戏最低允许售价和 1 中的最大值。所有计算按单个物品进行，与叠放数量无关。弹窗默认单价已经等于最终价格时直接确认，不重复输入价格；其他情况才填写计算结果，提交及手续费确认仍核对实际单价、数量和总价。

折扣保存在共享拍卖条目的 `auctionDiscount` 字段，按区隔离。旧字符串名单、旧对象或空折扣保持原定价行为，不自动打折；切换为手动或搜索模式时保留折扣但不应用。清空折扣恢复原行为，没有市场报价时继续保留物品。测试拍卖行显示计算单价但不提交。配置非法折扣会被拒绝，保存失败回滚列表和界面。

开始拍卖行上架阶段前，将背包提到拍卖行上方一次：背包已打开则按 I 关闭，等待正式快照确认关闭，再按 I 打开并确认；原本关闭则直接打开并确认。整段上架不再对每件物品重复开关背包，但每件仍重新读取坐标、模板、数量与悬停身份。上架结束、切换计算页前关闭背包。测试目录查价和测试上架弹窗分别在各自阶段准备背包；切页、交易弹窗或取消发生在切换途中时停止操作。正式完整流程仍先撤回全部旧单；显式上架续接入口只处理当前剩余背包，不撤回已经确认的挂售，且必须从无弹窗的登录页开始。

按自己的在售列表判断 15 项上限。每次确认上架前核对实例、模板、数量、单价和单件模式；提交后核对新增挂售及背包物品离开。结果未确认不重试提交。

上架编辑框之后还有手续费确认框。正式 `auction_house` 快照绑定拍卖行当前待提交的物品实例、数量、单价及计价方式，同时读取确认文字中的总价、手续费和实际按钮位置；不能用通用弹窗遗留的丢弃实例字段代替。确认前核对本次计划、总价和可支付手续费的金币，确认后仍必须等到新增挂售及背包实例移除。外来弹窗、数据不符、余额不足或结果未确认时停止，不重复提交。已有未处理的手续费确认框也会阻止正式流程和“测试拍卖行”继续操作。

先撤回登录页全部在售物品，包括人工挂售、上架时间未知、未满一天、未匹配当前拍卖行配置的物品；不再按上架时长或旧处理方式筛选。全部撤回后重新读取背包，按当前拍卖行名单与查价方式登录；不匹配或没有有效价格的物品留在背包。原“旧挂售处理 / 挂售满多少小时”控件已移除，旧 JSON 字段只保留兼容，不参与执行。上架记录仍保存在账号配置目录的 `auction-listings`，按账号和真实角色名隔离，用于记录本次结果，不限制撤单或重上架。

下架前按当前列表布局定位和滚动，并核对悬停挂售 ID；已从登录页消失的记录直接跳过，不另行处理成交。确认框必须绑定当前挂售。之后同时确认在售行消失和背包数量增加，确认登录列表已清空才进入上架阶段。物品返包合并叠放时按模板总数量核实。历史“不再上架”记录不再屏蔽本次配置匹配的物品。按先丢弃 / 出售再进入拍卖行的配置使用，本次不增加批量撤单的背包容量调度。

## 仓库与摆摊

仓库只配置角色名、选中快捷键。每 200ms 检查正式状态，每隔至少 2 秒才尝试选择 / 交互；未到场、未开摊、首件未出现就持续等待，停止可取消。选中后 C，核对摊位所属对象 ID。

按实际显示顺序购买第一件。Shift + 右键打开数量框；库存为 1 时直接等待待购买清单。购买数量为 `min(金币 / 单价取整, 库存, 数量框上限)`。先确认进入待购买清单，再点击最终购买；同时核对金币扣除、背包增加和清单清空。单价为零不交易，买不起时跳过转移，不购买第二件，不增加金币预留规则。

他人摊位购买列表使用摊位内物品编号，首件编号可以为 0，与背包实例 ID 不同。正式快照保留合法编号 0，仍核对商品表编号、模板、数量及摊主身份；购买悬停使用可空编号，`null` 表示没有悬停，`0` 表示确实命中编号 0 的商品。关闭或外来弹窗遮挡时不能把空悬停发布为编号 0。

整组放入菜篮子后，上方商品行可以保留为数量 0；读取仍校验该行身份，但不给它点击坐标或悬停身份。菜篮子独立提供经过校验的坐标与悬停编号，外来弹窗会遮断这些操作。Shift 与右键之间、右键释放与 Shift 释放之间保留短暂的输入间隔；这是组合键报告时序，数量框出现、数量正确及交易结果仍以正式快照确认。

摆摊使用配置单价、原计划数量，每批最多 10 项。开启后持续等待出售，只有原计划物品数量减少、金币达到计划收入、挂售项耗尽才能确认本批售罄；关窗或手动收摊不能替代成交证明。不核对买家身份。批次全部结束后才返回挂机。摆摊所得金币不会再转移一次。

当摊位窗口仍打开、清单已经清空并显示停止出售，但背包或金币尚未确认时，最多继续核对 8 秒，等待三项成交证据齐全；不会立刻判为中断，也不会凭空清单判断成功。确认失败仍停止，取消始终可响应。

## 数据适配与验证边界
