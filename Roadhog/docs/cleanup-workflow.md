# 清包与交易流程

## 使用与兼容

- 主界面原“登录”按钮改为“清包”，手动点击先确认，按清包页所选项目执行。运行中的账号通过同一 worker 插入流程，先停止选新怪并处理当前战斗；空闲账号先清包，再按原模式启动挂机。
- 四个项目顺序固定：出售 / 丢弃 → 拍卖行 → 转移金币 → 摆摊。可分别勾选。旧配置默认只启用普通清包。
- 自动触发遵守自动开关、背包阈值和 25 分钟完整清包冷却；保留冷却期间可丢弃的行为。自动永不执行转移金币或摆摊，也不显示确认弹窗。
- 每个 worker 会话仅允许一个请求；停止取消整个流程，未完成请求不继承到下一次启动。发生未确认的交易会使 worker 报错停止，不能假定成交后继续。丢弃被攻击打断时，先处理战斗再重新检查背包。
- 状态列显示“清包中 / 等仓库 / 摆摊中”，悬停显示当前步骤、等待秒数或剩余项数；正常进度不占用原告警通道。

## 路径和物品

新增拍卖行路径、摆摊路径编辑页，复用现有录制、保存、选择、删除、复制、单次执行功能。清包、拍卖行、摆摊路径均从挂机点录起。流程从第一个点执行，不能使用“最近点”跳过路径前段。

普通出售完成后逆走清包路径；拍卖行完成后逆走拍卖行路径。转移金币和摆摊共用一次摆摊路径，先购买再出售。结束时按回城键，确认坐标迁移，再走复活路径，绝不逆走摆摊路径。所有已选阶段的路径、仓库名和按键先预检，避免执行一半才发现后续路径未配置。

白名单优先保护；拍卖行和摆摊名单中的物品不进入普通出售 / 丢弃。两份交易名单重叠时拍卖行优先；未开启拍卖行、满额或查价不可用时也不降级出售。摆摊计划在购买仓库物品之前冻结实例和数量；买入物品即使合并进同一叠，也不会增加本轮出售数量。

## 拍卖行

通过 F8 选择交易中介：名字“摩比隆”或正式快照确认标题为“交易中介”。按 C 后等待真实对话和“委托交易”控件，开窗验证。进入后先到计算页领取已售金币，确认背包金币增加且结算金额清零，再处理挂售。

拍卖行路径增加与清包路径一致的“刷新附近 NPC”及下拉选择。选择后点击“保存到列表”，NPC 名称保存在该路径的 `AuctionNpcName`，独立于清包商人名称。正式流程及“测试拍卖行”都使用保存的名称，同时验证交易中介身份；未配置名称的旧路径继续按原来的名字 / 标题规则选择。F8 未选中时会重试，期间轮询目标数据，停止可取消。

支持手动单价、弹窗最低参考价。自动方式不使用保留的手动价格；最低参考价与最低允许售价是两个字段。没有有效报价、价格不合法、手动价格留空时保留物品。搜索计算算法尚未定义，因此正式流程保留该模式的物品并记录原因；现有“测试拍卖行”仍可搜索报价，且不提交交易或领取金币。

按自己的在售列表判断 15 项上限。每次确认上架前核对实例、模板、数量、单价和单件模式；提交后核对新增挂售及背包物品离开。结果未确认不重试提交。

旧挂售默认保持。可选“取回并重新定价”或“取回，不再上架”，默认满 24 小时。客户端只给显示天数，无法证明人工旧单的真实上架时间，因此只按本脚本成功挂售后的持久记录处理；未知时间的旧单保持。记录位于账号配置目录的 `auction-listings`，按账号和真实角色名隔离。

下架前按列表布局定位和滚动，并核对悬停挂售 ID；确认框必须绑定当前挂售。之后同时确认在售行消失和背包数量增加。物品返包合并叠放时按模板总数量核实。选择“不再上架”的模板会记入取回记录，在该模式保持期间不会被后续清包立即重新登记；要恢复上架需更改旧挂售处理方式。

## 仓库与摆摊

仓库只配置角色名、选中快捷键。每 200ms 检查正式状态，每隔至少 2 秒才尝试选择 / 交互；未到场、未开摊、首件未出现就持续等待，停止可取消。选中后 C，核对摊位所属对象 ID。

按实际显示顺序购买第一件。Shift + 右键打开数量框；库存为 1 时直接等待待购买清单。购买数量为 `min(金币 / 单价取整, 库存, 数量框上限)`。先确认进入待购买清单，再点击最终购买；同时核对金币扣除、背包增加和清单清空。单价为零不交易，买不起时跳过转移，不购买第二件，不增加金币预留规则。

摆摊使用配置单价、原计划数量，每批最多 10 项。开启后持续等待出售，只有原计划物品数量减少、金币达到计划收入、挂售项耗尽才能确认本批售罄；关窗或手动收摊不能替代成交证明。不核对买家身份。批次全部结束后才返回挂机。摆摊所得金币不会再转移一次。

## 数据适配与验证边界

新增读取仍封装在本地只读 `InventoryInteractionDecoder` 适配器中，沿用 `auction_house`、`personal_shop` 正式快照渠道与会话生命周期；业务仅调用 `IRoadhogSnapshotReader`。捕获通过完整字段与结束校验，读取失败由 provider 保持之前的正式值，不向业务发布伪空值。所有实际操作均经已有键鼠适配器，不调用客户端函数、不发包。

布局依据 `aion202609091125.json`：`2CC800 / 2D1B20 / 2D3650`（他人摊位、单价、数量），`2E5520 / 2E6AE0 / 2EC840 / 2E2160`（挂售、容量、上架、下架确认），`5E62D0 / 5D73F0 / 5DA1E0`（网格、列表、表头及分页），`22B2F0`（收摊控件）。读取边界检查和外来弹窗遮挡会禁止点击。

本次自动化验证包括配置持久化、独占 / 取消、路径衔接、交易完整模拟、解码字段故障、外来弹窗、容量与价格边界及旧功能回归。2026-09-20 隔离构建通过（0 警告、0 错误），完整回归 665 项全部通过，其中新增清包流程专项 10 项；日志位于 `.tmp/cleanup-workflow-check2.log`、`.tmp/cleanup-final-regression.log`。

新增提交出售、下架、购买和领取金币尚需实机对照；本次构建输出隔离在仓库 `.tmp`，没有自动覆盖桌面运行目录。
