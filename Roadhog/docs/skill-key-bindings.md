# 技能按键自动匹配

技能树决定施放优先级；技能栏位置决定实际按键。战斗、起手、HP/MP/状态/DP 维护、精灵召唤/提速/宝宝维护、组队治疗与选定技能的解状态共用一次启动映射。原有触发条件、冷却、连续技判断不变。

- 每次启动等待游戏场景可用，再读取当前页的主栏和 Alt 栏，共 24 格。运行期间移动技能或切换技能栏页面，需要停止并重新启动。
- 主栏依次为 `1..9,0,-,=`；Alt 栏依次为 `Num1..Num9,Num0,Num+,Num-`，与用户按键面板及账号 2 的召唤/护膜配置一致。这是约定的游戏第二快捷键，不读取或推测游戏自定义按键。
- 以技能 ID 精确匹配；显式配置的技能等级不会被其他等级替换。旧的仅名称配置只在名称对应唯一栏位技能时匹配。
- 重复放置优先主栏，再优先左侧。物品、宏、Ctrl 栏、其他页面不参与技能匹配。
- 未放入两栏的技能提示并跳过，不沿用保存的旧按键。连续技子技能有独立位置时用独立位置；没有独立位置时，仅当技能元数据确认前后链关系，才共用父技能键。
- 刷新技能显示自动按键；启动仍重新识别。预览不是运行状态，也不覆盖保存的键值。
- 系统操作、药品、宏和宝宝攻击指令继续手动设置。召唤/提速/精灵开怪与解状态新增技能选择，选择具体技能即自动匹配；留空则保留手动操作。旧配置只有按键、没有技能身份的这几项，需选择一次具体技能后才能随拖动自动匹配。

## 本地适配器和快照

`Infrastructure/Vmm/QuickbarDecoder.cs` 封装只读布局。基于本地 `Desktop/aion/Game.dll`（2026-09-09 导出）分析，2026-09-22 在账号 2 / Tone 实读验证；偏移限定在适配器内。当前页索引、两栏表项、UI 控件类型和技能 ID 交叉校验，完整捕获前后复读；短读、非法指针或拖动中途变化均拒绝发布。

类型化 `quickbar` 通道在 `AionVmmSnapshotChannels` 注册并随目录封存。Provider 统一持有上一份可信快照，冷启动由 `RoadhogSnapshotReader` 重试，工作线程等待且可取消。业务层仅用正式快照生成每次启动的执行映射，无原始内存读取、质量降级或失效时间判断。映射仅修改 worker 的配置副本，不改用户配置文件。

相关测试在 `Roadhog.Tests/SkillBindingTests.cs`。只执行 `--test-filter=skill binding` 及变更涉及的精灵/维护/技能 UI/快照/启动流程回归，不运行全量测试。

## 起手技能列表

- 保留“启用起手技能”，列表支持添加、删除、上移、下移，每项按当前技能栏自动匹配按键。
- “依次释放全部”默认不勾选：从上到下跳过冷却、缺失或未绑定的技能，只释放第一个可用技能。勾选后按列表顺序依次释放所有可用技能，再进入正常技能流程。
- 每项沿用释放确认和超时处理；零冷却技能每个目标只处理一次。当前目标完成后不会因为技能冷却结束再次执行起手列表。换目标重置进度，同一服务端对象仅实体编号变化时保留进度。
- 精灵的执行顺序保持“宝宝攻击 → 按后延迟 → 起手技能列表 → 正常技能”，列表执行期间仍遵循卡刀规则，停止会中断后续项。
- 配置保留 `Skills.OpeningSkill` 对象，新增 `ReleaseAll` 与有序 `Skills` 数组。旧对象没有数组或数组为 `null` 时，将原 `SkillId/SkillName/Key` 作为一项；显式空数组表示清空，不再恢复旧字段。界面保存时同步第一项至旧字段，旧版程序最多读取第一项，不能执行完整列表。
- 专项测试：`--test-filter=opening skill`；相关回归：`--test-filter=attack weave`、`--test-filter=skill binding`、`--test-filter=spiritmaster opening attack key`。
