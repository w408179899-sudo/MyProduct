# 技能按键自动匹配

设置页只显示技能栏释放的一棵执行树，决定施放优先级；技能栏位置决定实际按键。战斗、起手、HP/MP/状态/DP 维护、精灵召唤/提速/宝宝维护、组队治疗与选定技能的解状态共用一次启动映射。旧配置迁移及兼容档案见[统一技能栏释放](skill-release-migration.md)。

- 每次启动等待游戏场景可用，再读取当前按键模式支持的栏位。运行期间移动技能、切换技能栏页面或修改按键模式，需要保存后停止并重新启动。
- 技能页提供两个互斥选项，按账号保存到 `ScriptSettings.QuickbarKeyMode`。默认 `Numpad`（小键盘改键）只读前两排，共 24 格；缺少新字段的旧配置继续使用此模式。第一排依次为 `1..9,0,-,=`，第二排为 `Num1..Num9,Num0,Num+,Num-`，旧单键输入时序不变。
- `GameDefault`（游戏默认键）读取三排，共 36 格；第一排数字键，第二排 `Alt+1..9,0,-,=`，第三排 `Ctrl+1..9,0,-,=`。这是约定的游戏绑定，不读取或推测任意自定义按键；玩家应在游戏中保留相应绑定。技能、起手、维护、组队及食物快捷键共用此模式。
- 以技能 ID 精确匹配；显式配置的技能等级不会被其他等级替换。旧的仅名称配置只在名称对应唯一栏位技能时匹配。
- 重复放置优先靠前的排，再优先左侧。物品、宏、当前模式不支持的栏位和其他页面不参与技能匹配。
- 未放入当前模式支持栏位的技能提示并跳过，不沿用保存的旧按键。连续技子技能有独立位置时用独立位置；没有独立位置时，仅当技能元数据确认前后链关系，才共用父技能键和实际栏位。
- 刷新技能显示自动按键；启动仍重新识别。预览使用尚未保存的 radio 选择，经独立 RPC 方法传递；切换模式会失效旧预览，异步读取完成后核对模式版本，避免旧结果覆盖新选择。预览不修改运行中 worker 或保存的键值。
- 系统操作、药品、宏和宝宝攻击指令继续手动设置。召唤/提速/精灵开怪与解状态新增技能选择，选择具体技能即自动匹配；留空则保留手动操作。旧配置只有按键、没有技能身份的这几项，需选择一次具体技能后才能随拖动自动匹配。

## 可选技能分类

- DP、激活、条件、反击和连续技后续段优先按各自机制分类。其余技能按 XML 中明确的伤害效果识别主动攻击；附带减速、降防、晕厥或增益不会把攻击招式归入状态技能。纯增益和无伤害的减益沿用状态分类。
- 当前候选中能展开后续分支的连续技起手只在“连续技”树中显示，完整保留父子关系；普通分类不再重复列出。没有可见后续段的起手仍保留普通分类，隐藏的被动技能不会使起手消失。
- 展示分组不改变起手的主动释放性质、后续段身份、原始 XML 标签或保存的等级。专项回归使用真实 `Source/client_skills.xml`：`--test-filter=skill category`。

## 刷新全部已配置技能

- 技能页右侧的“刷新全部已配置技能”使用统一刷新与保存入口。以当前页所选模式支持的栏位为准：配置 IV、栏位放 III 时，更新为 III 的真实技能 ID、名称及元数据，不使用已学最高等级代替。
- 更新当前 `QuickbarSkills.ExecutionTree` 执行树、起手列表、HP/MP/状态/DP 维护、组队治疗与三类净化，以及精灵 DOT、召唤/服从手印、宝宝攻击、宝宝回血和宝宝增益。精灵设置窗口未打开、正在打开或已关闭均参与刷新。旧自动树、系统树和手动映射作为兼容档案保留，不参与刷新或当前攻击调度。
- 同名多个等级同时放入两栏时，取栏内最高等级；重复槽位、物品和不支持的栏位不扩大技能候选。配置更新后沿用自动保存，保留规则顺序、手动按键、阈值、维护时机、冷却及延迟。执行树只刷新自己的既有节点，保持顺序和层级；明确使用技能栏释放的空树保持为空，不从旧档案恢复。
- 根技能未放入两栏时清理该分支；连续技子节点有独立栏位时按栏位等级更新，没有独立栏位时保留原技能身份及元数据，并继续检查下级节点。不会因为子技能未单独上栏而误删，也不会改成已学最高等级；执行时仍由原有元数据校验父子链关系并决定能否继承父按键。
- 栏位技能身份无法匹配或操作取消时，不更新候选、配置或保存文件；确认未放入两栏的技能仍沿用原有清理行为。
- 按具体 ID 读取保留生活技能等栏位技能的真实详情，避免未配置的回城/采集技能阻止整次刷新；普通全量候选读取仍按原设置过滤生活技能并合并最高等级。
- 技能页的“刷新技能栏”和维护/精灵窗口的普通“刷新技能”仍只更新候选/预览，不自动替换或保存已选配置。
- 专项回归：`--test-filter=configured skill refresh`。

## 本地适配器和快照

`Infrastructure/Vmm/QuickbarDecoder.cs` 封装只读布局。基于本地 `Desktop/aion/Game.dll`（2026-09-09 导出）分析，2026-09-22 在账号 2 / Tone 实读验证；偏移限定在适配器内。当前页索引、两栏表项、UI 控件类型和技能 ID 交叉校验，完整捕获前后复读；短读、非法指针或拖动中途变化均拒绝发布。

类型化 `quickbar` 通道在 `AionVmmSnapshotChannels` 注册并随目录封存。三排模式使用独立的 `quickbar_three_rows` 与 `skill_availability_three_rows` 通道，避免两排快照被三排请求当作完整结果。可用性会话也按模式隔离，第三排沿用相同的表项、类型、指针、复读与场景身份校验。Provider 统一持有上一份可信快照，冷启动由 `RoadhogSnapshotReader` 重试，工作线程等待且可取消。业务层仅用正式快照生成每次启动的执行映射，无原始内存读取、质量降级或失效时间判断。映射仅修改 worker 的配置副本，不改用户配置文件。

## 组合键输入（2026-10-31）

- `KmBoxNetKeyboardInput` 串行发送：修饰键按下并等设备应答 → 主键按下 → 保持 10ms → 松主键 → 松修饰键。没有额外前置或松键后等待。整个序列占用同一个输入锁，普通按键、鼠标和重置操作不能插入组合键中间。
- 取消和发送异常均尝试用不可取消的 token 释放主键与修饰键；主键松开失败也继续尝试松开修饰键。设备无应答仍作为输入失败处理，不能承诺硬件故障时已成功释放。
- 不把修饰键和主键合并成一份同时按下的报告：脚本1稻草人测试中该方式曾将 `Ctrl+2` 识别成主栏 `2`。采用独立顺序报告的短时序。
- 短时序探针的 53 次输入、15 组观察均确认预期技能，未观察到错主栏；平均输入调用约 24.8ms。一次输入调用不等于一次成功施法，连续输入会受冷却、动作和连续技窗口影响。这些观测不能推导长期零误按率。
- 正式输入类接入后，脚本1 / FONE 对稻草人再测 8 组、26 次输入（含 23 次组合键）；8 组均确认预期技能、未观察到错主栏。23 次组合键调用平均 25.29ms，范围 16.79–39.96ms。正式 provider 同时验证默认 24 格、新模式 36 格及 36 格可用性绑定；配置文件哈希未变，按键与设备租约均释放。未覆盖桌面运行包。
- 自动测试覆盖旧配置、三排完整映射、连续技实际位置、维护/食物、UI 保存、RPC 模式传递、第三排短读/变化、模式快照隔离、组合键取消/故障释放与输入串行化。

相关测试在 `Roadhog.Tests/SkillBindingTests.cs`。只执行 `--test-filter=skill binding` 及变更涉及的精灵/维护/技能 UI/快照/启动流程回归，不运行全量测试。

- 保留“启用起手技能”，列表支持添加、删除、上移、下移，每项按当前技能栏自动匹配按键。
