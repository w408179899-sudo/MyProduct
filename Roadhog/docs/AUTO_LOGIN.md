# 多账号自动登录

2026-10-24 实现。入口位于“设备/角色”和主界面“登录所选”。

## 使用

- 在“设备/角色”填写游戏账号、游戏密码并保存。密码使用 Windows DPAPI CurrentUser 加密；更换 Windows 用户或电脑后需要重新填写。登录信息不参与硬件指纹，单独修改它们不会要求重新验证 DMA。
- “登录所选”只处理列表左侧勾选的账号，确认配置中的角色进入游戏后停止登录操作，不开启挂机。
- “启动/启动所选”先读取目标电脑的状态；正确角色已经在线时直接进入原启动流程，否则从当前登录阶段接续。登录成功后通过原角色身份检查，再开启挂机。
- “停止/停止所选”可取消登录，释放按键和鼠标，再回收该账号后台。其他账号保持独立。
- 日志事件 `account.login.progress` 记录阶段，不记录密码或输入的验证码。

## 已接入的页面

```text
桌面第一个图标 → UU 主窗口 → 第一款永恒之塔加速
→ 启动游戏 → 启动器“开始游戏”
→ 密码登录页签 → 协议勾选 → 账号密码 → 登录
→ 可选验证码 → 游戏协议 → 服务器 → 种族创建限制通知
→ 按配置名称选角色 → 开始 → 勾选自由对战 → 确认 → 游戏世界
```

所有页面先识别再点击，可从其中任一已识别阶段进入。UU 已加速则直接启动游戏。找不到 UU 或 UU 不在前台时，按用户指定的桌面第一个图标 `(35,35)` 打开；其他窗口使用前台进程确认和鼠标位置反馈。

启动器目前支持已验证的 1280×730 客户区，“开始游戏”为相对客户区 `(980,625)`。SDO、UU、游戏按钮根据当前控件树和原生窗口客户区计算。未知弹窗、账号密码错误、目标角色不匹配会停止并显示原因。服务器目前支持已验证的“唯一在线且已选中服务器”；有多个服务器时不猜测行号。

单步骤等待上限 100 秒，总登录上限 10 分钟。超时后可再次点击登录，从当前页面接续。重复点击合并同一操作；登录尚未结束时切换到启动会提示等待，避免两个流程同时输入。

## 游戏阶段与旧窗口

`Game.dll + 0xD6CA90` 是游戏阶段值，设置函数为 `sub_180340E80`。静态调用链存于 [阶段证据](evidence/login-ui-2026-10-24/game-state-transitions.json)：

| 值 | 已知用途 |
| --- | --- |
| 8 | 游戏协议 |
| 10 | 服务器选择 |
| 11 | 等待界面 |
| 12 | 角色选择 |
| 18 | 角色选择过渡 |
| 15 | 游戏世界 |

旧协议、服务器、选角窗口在后续页面仍可能保留可见位，因此阶段值、消息框事件、目标角色和窗口几何必须一起匹配。进入世界还要求有效地图编号、本地实体、完整玩家和位置，并先排查可见消息框，避免退出提示与残留角色数据被误判为在线。确认入场后不会再次点击残留的选角按钮。

2026-10-24 新读取的阶段值来自静态数据交叉验证；历史 UI 回放里的阶段值是明确标记的合成字段，不能当作该次历史实机读数。集成后的实机点击验证由用户执行。

## 验证码模型

使用用户这次训练的 PARSeq-Tiny，checkpoint SHA256：

`fc1a369cedcc8012f94c7734f528745d0f6e6cc0433a059ca367b49a854f3bf1`

运行时使用 ONNX CPU，模型、token 表、校验值和许可放在 `Source/Login`。不依赖 `.tmp` Python 环境。导出脚本为 `tools/captcha_ocr/export_login_model.py`；C# 运行接口参见 [ONNX Runtime 官方文档](https://onnxruntime.ai/docs/get-started/with-csharp)。

100 张历史图片的 PyTorch、Python ONNX 和 C# 输出逐张相同，C# 图像预处理与 Pillow 输入张量逐项匹配。这是转换一致性验证，不是新的准确率统计。该模型此前 100 次在线首轮识别为 69/100；本轮没有提交新的在线验证码。

只提交完整的 6 位 ASCII 字母数字，不补位、不猜测缺字。图片从目标登录进程读取；先记录已有缓冲区，再点击换图，要求同一已知地址的完整图片内容发生变化且唯一，排除任意残留旧图。提交前复查图片和窗口。验证码错误按当前页面重新填写或刷新；连续无法获得有效图片时返回密码页，重新获取会话。账号密码错误不会无限重试。

## 适配器与数据边界

- `Application/Login/AutoLogin.cs` 是可模拟的状态流程，只读取 `LoginSnapshot`；不读取 DMA，也不看读失败、质量或时间戳。
- `Infrastructure/Login/Native` 封装已归档客户端布局。账号后台复用现有 `AionVmmGameApi` 连接、退役锁、设备租约和 KMBox，避免新增一个设备拥有者。
- `login_scene` 在 `AionVmmSnapshotChannels` 统一登记为 Stable。页面、目标控件和坐标构成不可拆分的决策帧，不能跨页面按字段拼接。内部失败保留同一会话官方值，首次读取失败等待；完整的进程不存在是正常业务状态。
- 符号初始化或原生读取抛出的 `VmmException` 在 provider 内等待、重试，不直接退出登录。诊断事件为 `vmm.login.read_retry`；相同持续错误最多每 10 秒记录一次，仍受登录取消及总超时约束。
- 程序安装在中文路径时，内置 MemProcFS 的符号缓存路径存在兼容问题。原生库按内容哈希放入 `%LOCALAPPDATA%/Roadhog/MemProcFS/<hash>`，明确绑定同一份 `vmm.dll` 和 `leechcore.dll`，符号由该目录下的 `Symbols` 保存。准备过程有跨进程互斥与文件校验，不移动账号配置、不修改系统的符号注册表设置。相关诊断为 `vmm.native.loaded`，`reason=unicode_symbol_path`。缓存根路径本身含非 ASCII 字符时先尝试 Windows 短路径；无法取得兼容路径可配置英文路径的 `MEMPROCFS_HOME`。
- 账号、DMA 连接、PID/EPROCESS/PEB、模块加载身份变化使旧会话失效。采集、验证、发布串行。可选的诊断文字不参与业务决策。
- 窗口枚举以同一进程的桌面身份匹配共享堆映射。某个后台线程的 TEB 无法读取时，可用同桌面其他线程验证过的映射继续读取该窗口；目标桌面映射缺失或不唯一、窗口字段不完整时仍在 provider 内重试。原生线程表尚未初始化时不发布“窗口不存在”。
- 账号密码只在输入阶段解密；配置克隆、IPC 和文件中保留密文。模拟测试不连接真实 DMA、不发送真实输入。

## 测试与更新

重点测试覆盖完整链路及中途接续、已在线/角色不符、慢响应、旧页面、取消、验证码重试、密文保存、进程隔离、UI 勾选语义、可信发布故障和模型转换。

编译需用 `RoadhogDesktopScriptRoot` 指向测试目录，避免改变运行中的程序。正式更新必须同时包含 EXE/DLL、deps/runtimeconfig、ONNX 运行库以及 `Source/Login`；只复制 `Roadhog.dll` 不足以运行识别。构建复制脚本已加入这些文件，文件被占用时会跳过该目录。
