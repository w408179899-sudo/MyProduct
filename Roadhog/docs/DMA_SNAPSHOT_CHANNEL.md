# DMA 稳定快照通道

Roadhog 的业务数据读取统一经过 `AionVmmSnapshotChannels` 和
`DmaStableSnapshotStore`。业务控制器不负责把读取失败转换成默认值，也不维护自己的
DMA 失败缓存。

## 新增数据读取

1. 在 `AionVmmSnapshotChannels` 注册一个强类型 `DmaSnapshotChannel<T>`。
2. 公共 `Read*Async` 入口调用 `ReadStable(...)`，并传入注册令牌；禁止传自由字符串键。
3. 参数化读取使用注册通道的分区键，例如技能 ID 集合；不同分区不能互相回退。
4. 读取成功才发布新快照。读取失败不覆盖最后成功值。
5. 如果一个批次允许部分成功，必须在 VMM 层提供字段有效性并实现合并；不能在业务层猜测
   `0`、`false`、空集合或缺失对象的含义。
6. 新进程、PID 变化、进程/模块消失或 VMM 连接重置属于生命周期变化，必须隔离或清空旧快照。

## 返回约定

- 普通读取：第一次成功发布后，瞬时失败返回最后成功数据，不再按 2 秒过期。
- 冷启动：从未成功读取过时仍返回失败，通道不会凭空构造数据。
- `RequireFresh=true`：本次读取失败就失败，不返回旧数据。用于确认框、不可逆操作及其他
  必须证明当前状态的安全读取。
- 合法的 `0`、`false` 和完整空集合都是可发布数据，不能按值判断读取是否成功。

代码中的 2 秒 `vmm.snapshot.fallback` 限制只用于抑制重复日志，不参与快照读取或返回。
