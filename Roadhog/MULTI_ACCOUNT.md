# 多账号客户端

默认启动 `Roadhog.exe` 打开多账号管理窗口。每个账号由同一个程序的无窗口后台模式承载，拥有独立 PID、VMM、KMBox、正式快照、业务状态和日志。主界面不创建游戏读取器或输入设备。

## 使用

- 原目录的旧账号会自动迁移，迁移前保留 `accounts.json.before-multi-account.bak`；只有原来使用设备的主账号继承旧版共用的 KMBox 和授权路径，其他账号需分别绑定。其他旧客户端用“导入旧配置”选择其 `config/accounts.json`。
- 界面导入会预检全部资料；同名同内容的路径/方案可复用，同名不同内容自动添加来源目录后缀，并同步修改账号与方案中的路径引用。原账号文件不覆盖；名单和地图复制到 `config/imported/<批次>`，保留各来源的规则。每个账号保留原有卡密授权路径及机器码授权路径；旧默认 `owner-license.json` 也会继承，仍按原签名与机器码验证。导入后必须重新验证硬件。
- 新账号在“硬件”中绑定物理 DMA、明确编号的 VMM 与 KMBox。验证通过后显示实际角色、DMA 和 KMBox 连接结果，需要明确确认后才能保存新绑定。授权操作只影响该账号。
- “设置”保留现有技能、路径、维护、清包、摆摊和雷达界面。需要读取或测试时，通过 IPC 在对应后台执行；只保存脚本配置不会为了通知而启动后台。
- 每行“启动”“停止”“清包”只影响该账号；左侧勾选用于批量启停。点击一行用于查看该账号详情和日志。
- 运行中的账号在角色名下方显示等级和职业，例如“50级 · 精灵星”。数据复用后台已有的角色可信快照，随状态刷新，不增加读取频率；未读到时不显示推测值，停止或重启后清除上次运行的信息。
- 启动中也可以停止。停止先取消运行和恢复意图、释放输入，再退出后台；后台无响应时会在期限内结束该进程。硬件断连时不能保证设备已收到释放指令，日志记录具体失败。
- 关闭主窗口收进托盘，账号继续运行。“退出程序”停止全部账号后退出。
- 主界面异常退出后，后台保持独立。再次打开时，使用账号 ID、进程 PID、启动时间、程序路径和认证管道重新接管，避免重复启动。

## 文件归属

| 内容 | 位置和归属 |
| --- | --- |
| 账号列表、各账号硬件与脚本设置 | 主配置目录的 `accounts.json`，主界面唯一写入 |
| 路径库 | 共用 `paths` 目录 |
| 脚本方案 | 共用 `profiles` 目录；使用同一方案的账号在下次启动读取它 |
| 雷达地图 | 默认共用 `radar-maps`；迁移账号可保留自己的地图目录，后台监视对应目录并刷新自身地图 revision |
| 清包、摆摊及拍卖名单 | 默认共用名单文件；迁移账号可保留自己的名单，手动启动、清包启动和进程恢复使用相同来源 |
| 账号后台日志 | 日志根目录下 `accounts/<InstanceId>` |
| 主界面日志 | 日志根目录下 `manager` |
| 后台启动描述、身份与运行意图 | 主配置目录下 `workers`；属于运行管理数据，不手工共用 |

共享 JSON 保存使用同目录临时文件及原子替换，后台只能读取账号配置。读取质量仍由原来的后台 provider 负责，主进程不创建业务快照缓存，也不经 IPC 驱动战斗 tick。

配置生效沿用已有功能：路径和方案按原工作流读取；雷达的即时更新保留；DMA、KMBox 和授权变更须先停止对应账号。共享方案内容的修改会影响使用该方案的账号，账号的目标、路径进度、技能冷却和恢复状态始终独立。

## 六个旧客户端的配置迁移

`tools/prepare_six_account_migration.py` 在新的输出目录生成配置副本，不修改或停止源客户端。它先完整备份六份配置（排除后台进程令牌及运行记录），再按旧启动顺序选取当前方案，为当前方案及其六类路径引用生成独立的“保留_脚本N_”名称。名单、地图及授权原件保存在每个账号的 `config/preserved/N` 中。

其余共享资料发生同名冲突时，优先按文件内有效 `UpdatedAt` 选择最新版本；没有该时间则按原文件修改时间。时间相同再按原修改时间、源目录编号决定。所有候选原件及每次选择的哈希、时间依据保留在迁移包中，当前保留方案不会被此规则覆盖。

`AccountConfig.BagCleanupNameListPath`、`RadarMapDirectory`、`OwnerLicenseGrantPath` 可覆盖该账号的默认共享来源，空值继续使用全局来源。这些字段及 `LicenseCredentialPath` 的相对路径均以主 `accounts.json` 所在目录为基准，方便整体移动配置包。运行中的账号须先停止才能切换资源来源。设置窗口、手动启动和进程恢复统一使用对应账号的资源。

迁移记录会列出原来已经缺失的路径；不会猜测补齐，也不会让其他账号的同名文件意外替代。未绑定硬件的占位账号只保留在原始备份。迁移依据已保存配置，未保存的界面改动不在副本内。启用迁移客户端前须停止对应旧客户端，避免争用同一设备。

## 重新读取并保存硬件配置

账号行的“设备/角色”打开独立硬件窗口，可修改 DMA、读取 VMM 编号及 KMBox 地址、端口和 MAC。点击“测试读取角色 / 检查设备”，核对实际读取的角色后，勾选确认并点击“保存硬件配置”。修改设备会使上次验证失效，取消窗口不保存草稿。

Windows USB 列表顺序不是 VMM 驱动编号。后台使用保存的明确映射；重启或插拔后编号仍可能变化。电脑重启后，六个账号全部保持停止并显示“待验证”，上次的自动恢复意图会清除。每个账号必须重新读取、确认并保存硬件配置，本次开机才允许启动；只读取、不确认保存不会解锁。仅重新打开客户端不会使同一次开机的验证失效。

验证会话保存在当前用户的 Windows 易失注册表项中，重启或用户注册表卸载后不保留；无法取得会话记录时拒绝启动。配置只保存已确认的会话标识，不记录“永久有效”的布尔值。每个新后台启动业务前还会读取角色并与已保存角色比较，不一致时阻止启动并提示重新验证，不循环重试错误配置，也不自动覆盖绑定。

首次迁移的账号若没有已保存角色，需要先完成上述读取、确认、保存。重启后遇到角色不匹配，可修改读取编号重新测试；两账号编号互换时，先停止涉及的账号再逐个保存。停止账号允许暂时保留重复的历史编号，运行中的设备仍由跨进程租约互斥保护。不会为保存一个账号而自动修改另一个账号的旧配置。

已停止或仅有闲置/恢复后台的账号，打开设备窗口前会先回收对应后台；正在运行业务的账号会提示是否先停止。重新测试后保存会更新角色名；保存之前仍须人工核对。角色名比较不能替代用户对 DMA、KMBox 实物连接的确认。

## 升级与回退

本版所有后台使用同一套程序文件。代码升级前使用“退出程序”退出主界面和所有后台，再替换文件；升级后可逐个或分批启动。单纯隐藏窗口不释放程序文件。当前不支持新旧版本并存或逐账号滚动升级。

保留 `--legacy-ui` 入口用于受控兼容排查；不要同时让旧界面与新后台占用同一个设备。回退旧版本前停止全部后台，保留配置和迁移备份。

## 验证

本次构建、测试结果和验证范围见 [验证记录](MULTI_ACCOUNT_VALIDATION.md)。启动、停止、强杀及主界面异常退出的处理与故障注入结果见 [稳定性审查](MULTI_ACCOUNT_STABILITY.md)。

新增测试覆盖真正的无窗口测试子进程、独立 PID、重复启动、崩溃恢复、恢复禁用、单账号卡住时其他账号仍可管理、停止超时、初始化取消、主界面接管、设备与授权隔离、输入释放、配置写失败、共享文件并发读取、导入冲突、界面和 IPC 契约。

测试后台仅由 `Roadhog.Tests.exe` 注入，正式程序没有绕过授权或操作真实硬件的 mock 参数。构建时需显式指定临时 `RoadhogDesktopScriptRoot`，防止项目既有 AfterBuild 自动复制到桌面脚本目录。真实硬件长期运行和客户机行为需另外验证，mock 结果不代表硬件性能实测。
