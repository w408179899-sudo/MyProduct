# WPF 公共主页（0.6.0）

桌面宿主使用 .NET 10 WPF + CommunityToolkit.Mvvm。默认启动 Mock，只加载配置，不自动启动账号或连接硬件。

## 页面与交互

- 脚本主页：账号名称与模式、VMM 库、DMA 设备绑定、进程选择、模块只读测试、KMBox IP/Port/MAC 与握手测试、账号状态、实际连接 PID、时长、循环数、动作数及启停。
- 账号配置：设备 URI、驱动、按名称或 PID 定位、探测和重试间隔、快照记录、DMA 参数、模块 JSON、删除与保存。
- 运行诊断：最多 100 条操作记录，导出结构化账号运行日志和状态诊断包。
- 编辑内容不会自动修改已运行的账号。保存前必须执行“测试读角色 / 验证配置”，硬件模式须取得明确角色身份、完成 KMBox 握手，并由用户确认角色与物理设备对应关系。单项模块头或握手测试不能开启保存。保存成功后更新已保存的账号；运行中账号拒绝修改。
- 修改任意字段（包括改回原值）、切换账号、取消、重测失败或执行单项诊断都会撤销本次验证。保存命令自身也检查配置版本，不仅禁用按钮。未保存编辑在切换账号、关闭窗口前提示，启动前要求保存。
- 单账号保存/删除保留其他账号对象与运行会话。整份导入保留原全体停止的语义。
- 测试状态只代表该次测试，不表示持续在线。账号列表中的 PID 来自实际运行会话，不使用编辑框 PID 冒充连接结果。
- 列表的“已确认角色”记录最近保存时确认的角色，属于配置证据，不是实时角色快照。导入配置逐项重新验证，任何一项失败都不替换现有配置；不信任文件里的历史角色记录。

## 角色读取与设备对应关系

交互借鉴 Roadhog 的 `TestVmmReadButton_Click` → `ReadPlayerForVmmDeviceAsync`：对选中的 VMM 设备实际读取玩家快照，显示角色供人确认，不将找到进程或读到 PE 模块头称为角色验证成功。

项目在 Bootstrap 实现 `IProjectCharacterVerification`，通过 `ProjectDesktopComposition.CreateProfileVerifier()` 传给 `AccountProfileVerifier`。`Register` 复用本项目正式运行的强类型 `ProjectReaders` 通道，返回一个仅通过 `ISnapshotReader` 读取角色身份的委托。不要在 UI 放游戏偏移或复制原始读取路径。若项目的角色通道允许“尚未进入游戏”，由该配置流程等到实际角色出现；不要将默认对象当作角色。

每次验证创建新的封闭目录和快照会话，不继承其他账号或上次测试的快照；角色读取成功后只做 KMBox Connect 握手，不运行业务模块、不发送按键。结束前重新核对进程和模块身份，生命周期变化则拒绝保存。整体设有 30 秒取消期限，项目实现必须遵守取消信号。

硬件配置必须绑定明确的物理 DMA 身份。已有启动流程会核验序列号、位置、原始索引、拓扑及驱动指纹；重启后顺序变化时拒绝连接，要求重新选择设备、读角色、确认后保存，不凭 `devindex` 自动猜测对应关系。

空模板故意没有游戏角色通道：未接入项目验证器时，硬件保存明确拒绝。Mock 可以显式通过模拟配置验证，界面标注“未验证真实角色”；首次启动的默认 Mock 配置自动执行同一模拟验证。Mock 结果不能用于 Hardware。底层配置存储仍负责序列化和结构校验，桌面配置录入流程负责上述验证与确认；直接调用底层存储不是角色验证。

## 代码边界

`MainWindow.xaml` 和 `Views` 负责布局。`ViewModels` 负责页面状态与命令，不调用原生库。文件对话框通过 `IDesktopDialogs` 隔离，硬件诊断通过 `IHardwareDiagnostics` 隔离，均可使用替身测试。

`Smart.Hosting.Windows.HardwareDiagnostics` 管理临时诊断连接。D3XX 枚举通过 `Smart.Dma.Worker --inventory` 在独立进程执行：私有标准流、先分配 Windows Job 再发送请求、10 秒期限、有限响应大小；超时/取消等待子进程退出。正式运行仍使用原有隔离 VMM 连接池和正式快照提供者。

KMBox 诊断只发送 Connect 协议包，用独立 UDP 套接字接收匹配响应，关闭时仅关闭套接字。它不使用会发送 ReleaseAll 的正常输入对象销毁路径。测试与运行共用设备租约，拒绝抢占正在使用的设备。

UI 每 500 ms 合并展示状态，属性值未变化时不发通知；最小化后停止展示刷新。账号表格启用虚拟化，操作记录有数量上限；UI 不调度脚本循环。

## 添加项目页面

1. 在项目自己的 ViewModel 中通过项目服务获取正式快照和业务操作。
2. 在 `ProjectDesktopComposition.CreatePages()` 返回 `DesktopPage("unique-id", "页面名称", "图标字符", viewModel)`。
3. 在 `App.xaml` 注册该 ViewModel 对应的 `DataTemplate`，内容为项目自己的 WPF View。

页面 ID 重复时启动失败并明确报错。公共主页不需要增加按游戏名称判断的分支，不包含角色、等级、战斗或卡密逻辑。页面生命周期及依赖由项目组合根负责，关闭时不能留下后台任务。

## 从旧桌面宿主迁移

`data/accounts.json` 结构不变，旧 DMA 绑定及 worker 超时配置在编辑保存后保留。运行目录改变时需要显式导入旧配置。新 `ProfileEditor` 位于 `.Desktop.ViewModels`，不再是 WinForms PropertyGrid 模型。公共框架增加单账号配置和会话目标展示 API，原批量保存接口保留。

使用 `scripts/New-Project.ps1` 生成项目；该脚本过滤运行产物并使用新的模板注册目录，避免递归扫描到旧验收副本中的同名模板。

验证范围：Mock 启停、VM 交互、配置隔离、worker 超时/取消、UDP 回环纯握手、WPF 页面绑定及截图。真实 DMA 枚举/进程选择和真实 KMBox 按钮路径仍需在设备空闲时独立验收，本轮不占用任何账号设备。
