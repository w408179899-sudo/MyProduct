# 实机验收

本阶段使用空闲 DMA、对应 DLL/固件、明确的目标测试进程；验证输入时再准备 KMBox 和可控测试桌面。公共框架验证不依赖游戏账号密码。

已提供 [ProbeTarget 与协议](PROBE.md)，用于在目标电脑产生已知完整值、合法零值和更新中数据。先用该受控进程验收读取与正式快照，之后再接具体项目映射。本机协议测试和替身传输测试不等同于真实 DMA 验收。

目标电脑已经有运行进程时，可先使用 [NativeSmoke](../validation/Smart.NativeSmoke/README.md) 读取其通用 PE 头，验证初始化、身份和同批有效/无效块隔离；再用 [SnapshotSmoke](../validation/Smart.SnapshotSmoke/README.md) 在该静态头和无效地址间切换，贯穿实际 provider 的冷启动、失败保持、恢复与会话重置。两者无需游戏偏移或账号密码。静态模块头不能替代动态半写、真实进程重启和物理断连验证。

[KMBox Connect 探针](../validation/Smart.KmBoxProbe/README.md) 可单独检查端点通信，不发送键鼠动作；握手通过后仍须在可控桌面验证输入与释放。三个诊断工具的离线回归统一运行 scripts/Test-Diagnostics.ps1，不连接真实设备。

## 记录环境

记录设备型号/标识、连接 URI、VMM 与相关原生 DLL 版本、KMBox 固件和端点、操作系统、目标进程与模块。USB 清单顺序不是 VMM devindex，先确认映射。测试结果连同账号配置、日志、快照记录和 CPU/内存测量一起留档。

## 先验收读取

1. 在目标电脑运行 ProbeTarget，将仍在运行的目标 manifest 复制到主控电脑，再按 [探针说明](../validation/Smart.HardwareProbe/README.md)指定空闲设备、DLL、manifest 和运行时长。该路径只读取测试目标，不初始化 KMBox。Console 的 `--probe <accountId> --config <path>` 可另行检查实际项目配置的进程选择和模块身份。
2. 先通过探针验证正常值、有效零值、撕裂时保持、计数持续变化和目标身份；完整空集合和部分字段已有框架离线测试，实际项目在 Infrastructure 注册自己的映射后还需对应验收。业务接口只读取正式快照。
3. 短暂读失败且会话身份未变化时，已有正式值、版本和时间保持；有效新字段一旦读到即发布。冷启动没有正式数据时等待且能取消。
4. 同一设备绑定多个账号，核对连接复用、队列上限和读取复用。使用两台设备时，再验证某台初始化/关闭缓慢不会阻塞另一台。
5. 测试进程退出、重新启动、模块更换和 DMA 断连恢复。明确的生命周期变化失效旧快照，新的会话不能消费旧代次数据。

## 再验收输入与停止

在可控桌面检查单键、相对移动、绝对定位、持续按下、优先级接管和显式释放。绝对定位需要现场校准；协议返回成功与屏幕实际落点分别核对。

验证暂停、停止、输入断连和重新连接。停止超时必须显示仍在清理，设备租约不能提前释放；恢复后重试清理成功才能重启。记录 native 调用最长返回时间和停止耗时。

## 持续运行

按实际账号数和通道规模持续运行，包含正常采集、部分读、间歇故障、输入竞争和日志轮转。观察 CPU 核占用、保留内存、句柄、队列等待、正式发布频率、重连次数和日志丢弃量。读取请求数、VMM 调用数和物理 DMA 事务数分别记录。

验收时间与负载必须写进结果，不用几分钟的合成样本替代数小时的设备运行。项目自己的字段校验和业务动作确认也应有独立测试。
