# 正式快照契约

## 唯一发布路径

注册 token + 当前会话 + 强类型分区 → 同键采集门 → 原始读取 → 校验/合并 → 校验会话代次 → 原子发布。

业务只能取得 PublishedSnapshot<T>，包括 Value、Stamp 和 CapturedAt。Stamp 是 (Generation, Version)，只对同一个通道和分区比较。数据必须采用不可变 record、ImmutableArray 或 ImmutableDictionary，不得发布后修改对象。

Version 在每次有效发布时增加，即使新值与旧值相等。失败返回原对象、原版本和原时间。Version 不等于物理 DMA 次数；底层驱动缓存仍可能返回相同数据。

WaitForChangeAsync 等待后续正式发布或新会话的首份正式数据，并支持取消。动作确认最终检查业务结果，不能只检查版本变化。

## 原始值与正式值分开

Smart.Data 的 RawRead、Field、ReadCompleteness 是提供者协议，Application 不引用这些类型。

- Complete：结构遍历完成；每个业务字段仍需校验。
- Partial：有效部分更新，不完整遍历遗漏的对象保留。
- Failed：没有可发布的更新；已有正式快照原样返回。
- Field.IsValid=false：字段中存放的 0/false/default 不得参与合并。

不能仅凭“数值不为零”判断读取成功。例如生命值 0、布尔 false、完整空列表都是有效业务数据。数据验证依赖结构、身份、字段读取结果以及具体领域的不变量。

ReplaceMerger 适用于完整值；CollectionMerger 提供稳定身份集合的字段合并。具体组合字段的不变量由项目 merger 校验，只有同一 Identity 才可用旧字段补齐。完整空集合可以清空，Partial 空集合保持原发布。

CollectionMerger 先找出重复或不可信身份，排除这些身份的全部观察值，再更新其他独立有效对象。只要存在身份歧义就不删除未出现的旧对象。复杂度为线性扫描加不可变字典更新，不进行两两比较。

## 会话与重连

SessionIdentity 显式包含：

- DeviceId：真实设备稳定身份。
- ConnectionId：每次真实连接建立产生的新 ID。
- AccountId、WorkerId：账号与本次 worker 身份。
- ProcessId、ProcessStartId：进程号与本次进程启动身份。
- ModuleId：模块身份，建议含模块路径、基址和版本/加载代次。

同账号同 worker 的设备重连、PID/进程启动/模块变化调用 Reset；账号或 worker 更换必须创建新会话。Reset 会原子更新 Generation 并清空旧发布；任何正在完成的旧采集都不能再提交到新代次。

硬件集成层负责检测真实生命周期并调用 Reset/Dispose。模板不猜测目标游戏进程，也不会仅根据错误文本判断它是否已经重启。

同步 Reset/Dispose 立即失效旧数据并异步发起取消，不在调用线程等待扩展回调。真正释放会话时必须 await DisposeAsync，收束所有代次的采集、观察者和取消回调；之后才能关闭共享连接与日志。回调异常在收束后汇总报告一次，后续清理可重试。框架 RuntimeSession 已完成该顺序；自行组合宿主时应使用 await using。

## 频率与容量

MinimumCaptureInterval 控制重复采集成本，属于提供者配置，不是正式数据的失败 TTL。失败重试为 25..250ms 有上限退避；故障诊断按键每两秒节流。正式快照在有效会话内不会因读取失败时间过长而过期。

相同键的并发请求串行提交，采集间隔内共享同一正式对象。每会话默认最多 256 个通道/分区条目，防止随意查询形成无限字典。

已有正式快照时，发起刷新最多等待 SnapshotProviderOptions.RefreshWait（默认 25ms）；超时返回原正式快照。采集仍由提供者持有，同键后续请求立即取得已有值，不排队发起更多采集；原采集一旦成功就立即发布。冷启动没有正式值时继续等待，支持调用方取消。

取消一个调用方不会取消其他调用方共享的采集。Reset 会取消旧代次的采集等待并唤醒读者；不响应取消的底层调用晚到时仍不能提交旧结果。SnapshotSession.Metrics 仅供基础设施观测捕获数、发布数、刷新等待超时和在途数量。

回放源可用提供者内部 ObservationId 标识同一帧，重复取得该帧不会伪造新发布。普通 DMA 读者不设置该字段，每次有效采集仍立即发布，包括值相同的采集。采集接口必须及时返回 ValueTask，不能在调用线程无限阻塞；同步 native 调用交给有界 DmaDispatcher。

读取器目前按需采集；低频通道需要业务使用时才读。需要后台采集时，应在提供者宿主按明确频率调度，不要让业务创建自己的 last-good 缓存。

多个不同通道不自动构成同一时刻的硬件原子快照。需要跨字段一致性时，定义组合通道并在采集器和合并器中验证，不以“同一 tick”替代一致性校验。

## 新通道必须提供

1. 正式业务类型及不可变性约定。
2. 强类型分区键；无参数通道用 NoPartition。
3. 原始读取器与字段/身份验证规则。
4. Replace 或 FieldAware 合并策略。
5. 有上限的采集频率、批次数量及数据规模。
6. 正常值、失败保留、冷启动、Partial、完整缺席和生命周期回归测试。
7. 更新该项目通道目录完整性测试。

当前模板目录为空。新项目按以上步骤注册实际通道，同时在模块 RequiredChannels 中声明；运行时限制模块只能读取已声明且已注册的通道。
