# 技能调度

`SkillScheduling` 是独立的 .NET 8 库。每个角色会话各自保存一份技能尝试状态。

游戏适配层每轮根据当前状态生成 `SkillCandidate<TId>`，填入技能标识、优先级、释放条件是否满足、执行函数，以及是否在继续上一次尝试。数值较小的优先级先执行，同优先级时先继续未完成的动作。执行函数可以在最终校验失败时返回 `false`，调度器会考虑下一个候选。已经发键或仍需占用这一轮等待确认时返回 `true`。

`SkillAttempts<T>` 保存首次施放的证据基线、确认窗口和补按时间。高优先级动作取得输入权时可以保留旧尝试。高优先级动作结束后，根据最新条件决定是否恢复旧尝试。已经观测到迟到的完成证据时，用 `FinishSuspended` 结束对应尝试。死亡、切换角色或结束会话时由适配层清除失效尝试。

游戏定义什么算成功，并把结果交给 `SkillConfirmationWindow`。例如自身护膜要看到对应 Buff，蓄力动作可以用消耗的充能确认。公共层统一处理等待、超时、补按节奏和取消。优先使用单调时钟，同一次尝试的重试和让位都沿用原来的确认窗口。

Roadhog 在战斗入口使用公共调度，普通技能用公共尝试状态保留基线，人物 Buff 用公共确认窗口。技能栏绑定、连招、冷却和 Buff 的判断留在 Roadhog 适配层。
